# ASTRAL_LOG 페이지 구조 상세 명세

## 1. 문서 목적

이 문서는 아웃게임 도감 화면인 `ASTRAL_LOG`의 화면 구성, 상태 전환, 입력, 애니메이션, 렌더 순서와 데이터 구조를 정의한다.

`ASTRAL_LOG`는 독립된 앱 형태의 사각 패널 화면이 아니다. 메인 메뉴의 배경과 시각 언어를 유지한 채, 메인 메뉴 안에서 관측 기록 열람 기능이 확장되는 **인라인 아카이브**다.

이 문서는 다음 작업의 기준으로 사용한다.

- 롤백 또는 충돌 이후 도감 UI 재구현
- ARMORY 및 RUN_CONFIG와 공통 UI 동작 통일
- 카테고리나 도감 항목 추가
- 입력 및 전환 애니메이션 버그 검사
- 밝거나 복잡한 배경에서의 가시성 검사

---

## 2. 핵심 경험

도감 화면은 다음 세 가지 인상을 동시에 제공해야 한다.

1. **메인 메뉴의 연장선**: 별도 씬으로 순간 이동한 느낌이 없어야 한다.
2. **원형 성도 탐색**: 목록을 단순히 위아래로 스크롤하는 대신, 거대한 관측 장치를 회전해 기록을 찾는 느낌이어야 한다.
3. **읽기 전용 기록실**: ARMORY처럼 구매를 요구하지 않고, 관측된 적·증강·보스의 정보를 열람하는 화면이어야 한다.

도감의 시각적 주인공은 우측 끝에 걸쳐 있는 거대한 원형 성도다. 목록과 상세 정보는 성도에 종속되지만, 읽기 편하도록 각각 독립된 좌표와 명도 계층을 가진다.

## 3. 화면 전체 구성

```text
+--------------------------------------------------------------------------------+
|                                                                                |
|                    목록 항목과 소형 별자리              거대한 원형 성도       |
|                    (회전 궤도를 따라 배치)        (우측 화면 밖까지 이어짐)   |
|                                                                                |
|  ENTITIES             작은 성도 + 항목명                       ┌─────────────  |
|  MODULES              작은 성도 + 항목명                       | ID            |
|  APEX                 작은 성도 + 항목명                       | 이름          |
|  BACK                                                          | 설명/상태     |
|                                                                └─────────────  |
|                                                                                |
+--------------------------------------------------------------------------------+
```

화면은 논리적으로 네 영역으로 나눈다.

| 영역 | 역할 | 배치 원칙 |
|---|---|---|
| 루트 메뉴 | 카테고리 선택 및 복귀 | 메인 메뉴 버튼의 기존 시작 좌표를 계승 |
| 원형 목록 | 현재 카테고리의 항목 탐색 | 성도의 외곽 궤도를 따라 배치 |
| 거대 성도 | 화면의 시각적 기준축 | 우측 끝에 중심을 두고 일부가 화면 밖으로 잘림 |
| 상세 정보 | 현재 항목 설명 | 성도 내부의 우측 중앙 영역에 고정 |

상단 ONEDOW 로고는 `ASTRAL_LOG` 진입 중 사라진다. 하위 화면에서 로고가 남아 목록이나 성도와 경쟁하면 안 된다.

## 4. 진입 및 복귀 구조

### 4.1 진입

`ASTRAL_LOG`는 별도 화면으로 페이드 전환하지 않는다. 메인 메뉴에서 도감 버튼을 선택하면 같은 캔버스 위에서 다음 순서로 전개된다.

1. 메인 메뉴 입력을 잠근다.
2. ONEDOW 로고와 기존 메뉴 묶음이 좌측으로 이동하며 페이드 아웃된다.
3. 기존 메뉴가 충분히 사라진 뒤 `ENTITIES`, `MODULES`, `APEX`, `BACK`이 위에서 아래 순서로 등장한다.
4. 원형 성도와 목록이 낮은 알파에서 나타난다.
5. 기본 카테고리와 첫 관측 항목을 활성화한다.
6. 전환이 끝난 뒤 입력 잠금을 해제한다.

권장 진입 길이는 약 `0.55초`다. 하위 버튼은 메인 메뉴 버튼이 사라지기 전에 먼저 보이면 안 된다.

### 4.2 복귀

복귀는 진입 애니메이션의 역방향 흐름을 사용한다.

1. `BACK`, `ESC`, 마우스 우클릭은 모두 같은 복귀 함수를 호출한다.
2. 입력을 즉시 잠근다.
3. 목록, 상세 정보, 성도가 우측으로 밀리거나 알파가 감소한다.
4. 루트 메뉴가 사라진 뒤 메인 메뉴가 좌측에서 원래 위치로 복귀한다.
5. 마지막 복귀 프레임을 렌더한 다음 도감 활성 플래그를 해제한다.
6. 호버와 임시 선택 상태를 초기화하고 입력을 해제한다.

활성 플래그를 애니메이션 종료 전에 끄면 배경 딤이나 UI가 한 프레임 사라져 플래시가 발생한다. 상태 초기화 역시 마지막 프레임 이후에만 수행한다.

### 4.3 권장 상태 모델

```cpp
enum class ArchiveTransition {
    Closed,
    Entering,
    Active,
    Leaving
};

struct ArchiveUiState {
    ArchiveTransition transition;
    float transitionT;
    int categoryIndex;
    int selectedIndex;
    int hoveredIndex;
    float currentAngle;
    float targetAngle;
    float angularVelocity;
    bool inputLocked;
};
```

씬 플래그, 전환 방향, 타이머를 서로 독립된 불리언 여러 개로 관리하면 불가능한 조합이 생기기 쉽다. 하나의 명시적 전환 상태를 사용하는 편이 안전하다.

## 5. 루트 카테고리 메뉴

### 5.1 항목

- `ENTITIES`: 일반 적 및 정예 적 기록
- `MODULES`: 증강 기록
- `APEX`: 보스 및 특수 개체 기록
- `BACK`: 메인 메뉴 복귀

### 5.2 디자인

루트 메뉴는 메인 메뉴의 공통 명령 버튼과 같은 구조를 사용한다.

- 동일한 영문 메인 폰트와 한글 보조 라벨
- 동일한 행 높이와 넓은 비가시 히트박스
- 동일한 좌측 안내 바 애니메이션
- 동일한 호버 색상 보간
- 동일한 클릭 펄스 및 퇴장 타이밍

눈에 보이는 텍스트 폭과 무관하게 행 전체를 클릭할 수 있어야 한다. 다만 히트박스가 원형 목록 영역까지 침범해서는 안 된다.

### 5.3 카테고리 색상

카테고리 색상은 콘텐츠 식별을 위한 보조 신호다. 텍스트 전체를 강하게 물들이는 대신 다음 요소에 제한적으로 적용한다.

- 활성 카테고리의 좌측 안내 바
- 목록 별자리의 선과 노드 광원
- 상세 정보의 얇은 기준선과 상태 라벨
- 성도의 일부 눈금 또는 선택 표시

프레임과 본문 텍스트는 공통 중립색을 유지한다. 권장 의미 색상은 `ENTITIES=시안`, `MODULES=녹색`, `APEX=금색 또는 절제된 주황색`이다.

## 6. 원형 성도와 목록

### 6.1 성도 배치

거대 성도의 중심은 화면 우측 끝 부근에 둔다. 전체 원이 화면 안에 들어오지 않으며, 일부 호만 보여 규모감을 만든다.

- 성도 반지름은 화면 세로 크기를 기준으로 계산한다.
- 중심점은 화면 우측 경계 바깥 또는 경계 가까이에 둔다.
- 해상도가 달라도 상세 정보가 가려지지 않도록 안전 영역을 유지한다.
- 내부를 가로지르는 방사형 선은 사용하지 않는다. 동심 호, 눈금, 선택 기준선만 남긴다.

### 6.2 항목 배치

각 목록 항목은 성도 외곽의 고정된 반지름에 배치한다.

```text
itemAngle = baseAngle + visibleOffset * itemAngleStep + currentAngle
itemX = chartCenterX + cos(itemAngle) * itemRadius
itemY = chartCenterY + sin(itemAngle) * itemRadius
```

항목은 다음 요소로 구성한다.

1. 항목별 소형 별자리
2. 별자리에서 뻗는 짧은 연결선
3. 항목 이름

별자리는 텍스트 바깥쪽, 즉 성도 외곽 방향에 둔다. 텍스트와 겹치지 않으면서 성도를 둘러싼 관측 대상처럼 보여야 한다.

### 6.3 위치 안정성

별자리 위치는 다음 값에 영향을 받으면 안 된다.

- 호버 시 텍스트 슬라이드 길이
- 항목 이름의 문자열 폭
- 상세 정보의 크기
- 선택 강조선의 길이

소형 별자리와 텍스트는 공통 항목 앵커에서 각각 계산해야 한다. 텍스트를 밀어내는 애니메이션이 별자리 좌표에 더해지면 호버할 때 별자리가 흔들리거나 순간 이동한다.

### 6.4 무한 목록

항목 수가 많은 `MODULES`는 원형 목록을 계속 회전할 수 있어야 한다.

- 표시 인덱스는 모듈로 연산으로 순환한다.
- 화면에는 제한된 수의 앞뒤 이웃만 렌더한다.
- 같은 위치에 두 항목이 겹치지 않도록 모든 카테고리가 같은 각도 간격 규칙을 사용한다.
- 마지막 항목과 첫 항목 사이도 일반 이웃과 같은 간격을 유지한다.
- 일반 증강에서 디버프 증강으로 넘어갈 때 중간 등급을 전부 통과하는 하드코딩 경로를 사용하지 않는다.

목표 인덱스로 이동할 때는 원형 인덱스의 최단 거리를 계산한다.

```cpp
int delta = WrapIndex(target - current, itemCount);
if (delta > itemCount / 2)
    delta -= itemCount;
```

### 6.5 카테고리별 간격

카테고리마다 항목 수가 다르더라도 화면상 기본 항목 간격은 통일한다. `MODULES`만 촘촘하고 `ENTITIES`는 넓은 구조를 만들지 않는다.

항목이 많으면 더 많은 항목을 한 화면에 압축하지 않고, 렌더 대상 수를 제한한 채 원형 스크롤로 탐색한다.

## 7. 소형 별자리 디자인

### 7.1 공통 구성

모든 소형 별자리는 아래 순서를 따른다.

1. 중심 코어
2. 주변 별 노드
3. 노드를 잇는 가는 선
4. 노드 위치의 `CircleTexture` 광원

선은 노드보다 얇고 어두워야 하며, 중심 코어는 주변 노드보다 커야 한다.

### 7.2 고유 형태

각 항목은 가능한 한 고유한 별자리 형상을 가진다.

- 낮은 등급: 3~5개 노드의 단순한 도형
- 중간 등급: 비대칭 분기, 이중 고리, 보조 연결선
- 전설·신화 등급: 더 많은 노드, 다층 구조, 명확한 중심축
- 적 기록: 움직임이나 공격 방향을 암시하는 불규칙 구조
- 보스 기록: 큰 중심핵과 넓은 궤도를 가진 위압적인 구조

복잡도는 노드 개수만 늘리는 방식이 아니라 실루엣 차이로 구분한다.

### 7.3 목록용 CircleTexture

목록 별자리 노드의 `CircleTexture`는 **검은색 배경용 텍스처가 아니다**.

- 별자리의 카테고리 또는 등급 색상과 같은 광원색 사용
- 각 노드 중심과 정확히 일치
- 선택 항목은 광원 반경과 알파를 소폭 증가
- 비활성 항목도 완전히 사라지지 않는 최소 알파 유지

이 텍스처는 우측 상세 정보 뒤의 대형 `CircleTexture`와 목적과 색상이 다르다.

## 8. 우측 상세 정보

### 8.1 위치

상세 정보는 거대 성도 내부의 우측 중앙에 둔다. 화면 끝에 과도하게 붙이지 않고, 긴 한글 문장이 들어갈 수 있는 안전 폭을 확보한다.

상세 정보의 좌표는 성도 회전이나 목록 텍스트 슬라이드에 영향을 받지 않는다. 성도 중심을 기준으로 한 상대 좌표를 사용하되, 화면 안전 영역으로 제한한다.

### 8.2 정보 순서

```text
ID : MODULE_000

공격력 증가

RECORD SUMMARY
공격력 +9 / 중첩마다 기본 피해 누적 상승 / 초반·후반 모두 안정적인 화력 보강

CLASS : MODULE_ARCHIVE | STATUS : ACQUIRED
RECORD TYPE : AUGMENT MODULE | SOURCE : IN-RUN

[ ARCHIVE_READ_ONLY ]
```

카테고리별 내용은 달라도 계층은 유지한다.

| 계층 | 내용 | 시각적 우선순위 |
|---|---|---|
| 식별자 | 내부 ID | 낮음 |
| 제목 | 적·증강·보스 이름 | 가장 높음 |
| 요약 | 기능과 행동 설명 | 높음 |
| 메타데이터 | 분류, 상태, 출처 | 중간 |
| 상태 라벨 | 읽기 전용 여부 | 포인트 |

`MODULES` 도감에는 비용, 구매 버튼, 해금 명령을 표시하지 않는다. 도감은 순수 열람 화면이며 ARMORY의 거래 정보와 구분되어야 한다.

### 8.3 텍스트 갱신

빠르게 항목을 훑을 때 텍스트가 프레임마다 즉시 교체되면 깜빡임이 심해진다.

- 선택 확정 또는 짧은 호버 안정 시간 이후 데이터를 교체한다.
- 처음 `0.08초`만 제한적인 문자 디크립팅 효과를 사용한다.
- 이후 약 `0.12초` 동안 알파가 안정되며 정상 텍스트로 정착한다.
- 제목과 본문 전체를 장시간 깨뜨리지 않는다.

## 9. 우측 상세 영역의 이중 CircleTexture

우측에는 상세 텍스트의 가독성을 확보하기 위한 **대형 CircleTexture 두 장**을 사용한다. 이 항목은 목록 별자리 노드의 광원과 완전히 별개다.

### 9.1 후면 검은 CircleTexture

- 색상: 검은색
- 크기: 거대 성도와 상세 정보 영역 전체를 덮을 정도
- 목적: 흰색, 검은색, 컬러풀한 배경 모두에서 상세 텍스트 대비 확보
- 위치: 상세 정보와 성도보다 뒤
- 형태: 별도 절차적 원형 그라데이션이 아니라 프로젝트의 실제 `CircleTexture` 사용

화면에 검은 사각 패널처럼 보이면 실패다. 원의 중심이 화면 밖에 걸치더라도 부드러운 원형 감쇠가 보이도록 충분히 크게 배치한다.

### 9.2 전면 보라색 CircleTexture

- 색상: 절제된 보라색 또는 현재 성도 포인트 컬러
- 크기: 후면 검은 텍스처의 약 절반
- 목적: 상세 정보가 성도의 초점 지점에서 투영되는 느낌 제공
- 위치: 검은 텍스처 위, 성도 선과 텍스트 아래
- 알파: 텍스트를 물들이거나 배경을 밝게 태우지 않는 수준

### 9.3 금지 사항

- 두 대형 텍스처를 목록 별자리 노드에 적용하지 않는다.
- 검은 텍스처 대신 임의의 `DrawRadialGradient`를 추가하지 않는다.
- 상세 정보보다 앞에 렌더해 글자를 흐리게 만들지 않는다.
- 모든 노드의 CircleTexture 크기를 일괄 두 배로 키워 상세 영역 수정으로 대체하지 않는다.

## 10. 입력 모델

### 10.1 마우스 휠

- 한 번의 휠 노치가 한 항목 이동을 요청한다.
- 기존 요구에 맞게 휠 방향은 UI의 원형 회전 방향과 일치하도록 반전 적용한다.
- 연속 입력은 목표 인덱스만 누적하며 현재 각도를 순간 변경하지 않는다.
- 단위 시간당 최대 이동량을 제한해 매우 빠른 휠 입력에도 애니메이션이 무너지지 않게 한다.

### 10.2 드래그

- 마우스 버튼을 누른 채 위아래 또는 원호 방향으로 끌면 성도가 회전한다.
- 드래그 중 현재 각도는 부드럽게 추종한다.
- 버튼을 놓으면 가장 가까운 항목에 스냅한다.
- 화면 끝에서 반대편 항목으로 갑자기 순간 이동하는 표현은 금지한다.

### 10.3 클릭

- 루트 메뉴 클릭: 카테고리 변경
- 목록 항목 클릭: 해당 항목 선택 및 상세 정보 갱신
- `BACK` 클릭: 복귀 애니메이션 시작

### 10.4 키보드

- `ESC`: 복귀
- 방향키 또는 `W/S`: 이전·다음 항목
- `Enter`: 현재 항목 확정

전환 애니메이션 중 모든 입력은 무시한다. 동일 프레임에서 카테고리 변경과 항목 선택이 동시에 처리되지 않게 한다.

## 11. 회전 및 보간 규칙

회전은 목표 위치의 반대 방향으로 먼저 움직이거나, 목표 근처에서 튀면 안 된다.

### 11.1 권장 처리

1. 현재 각도와 목표 각도의 차이를 `[-PI, PI]`로 정규화한다.
2. 각도 차이에 기반해 목표 속도를 구한다.
3. 최대 각속도를 제한한다.
4. 현재 속도를 목표 속도로 감쇠 보간한다.
5. 목표 근처에서는 필드별 작은 임계값으로 스냅한다.

```cpp
float delta = NormalizeAngle(targetAngle - currentAngle);
float targetVelocity = Clamp(delta * response, -maxSpeed, maxSpeed);
angularVelocity = Damp(angularVelocity, targetVelocity, damping, dt);
currentAngle += angularVelocity * dt;

if (std::abs(delta) < angleEpsilon &&
    std::abs(angularVelocity) < velocityEpsilon) {
    currentAngle = targetAngle;
    angularVelocity = 0.0f;
}
```

항목의 화면 좌표에 다시 별도의 위치 Lerp를 적용하면 이중 보간으로 흔들릴 수 있다. 원형 위치는 보간된 각도 하나로만 계산한다.

## 12. 렌더 순서

권장 Z-order는 아래와 같다.

1. 공통 메인 메뉴 배경
2. 공통 글로벌 비네트 또는 사용자 설정 딤
3. 우측 후면 검은 CircleTexture
4. 우측 전면 보라색 CircleTexture
5. 거대 원형 성도의 호와 눈금
6. 비활성 목록 별자리와 연결선
7. 활성 목록 별자리와 연결선
8. 목록 텍스트
9. 상세 정보의 기준선과 장식
10. 상세 정보 텍스트
11. 루트 카테고리 메뉴
12. 전환 또는 입력 차단용 최상위 연출

텍스처 배치를 한 번에 모아 처리할 경우에도 논리적인 후면·전면 배치를 분리해야 한다. 특히 상세 정보용 CircleTexture가 텍스트 뒤에 있다는 보장이 필요하다.

## 13. 가시성 기준

도감은 다음 세 배경에서 모두 확인해야 한다.

- 거의 흰색인 배경
- 거의 검은색인 배경
- 숲, 용암, 네온처럼 색 변화가 많은 배경

### 13.1 텍스트

- 제목은 항상 최우선 명도
- 본문은 배경에 묻히지 않는 중간 이상 명도
- 비활성 목록도 존재 자체가 사라지지 않아야 함
- 활성/비활성 차이는 색상만이 아니라 알파와 좌측 기준선으로 함께 표현

### 13.2 알파 계층

정착 상태 기준 권장 계층은 다음과 같다.

| 계층 | 권장 알파 | 대상 |
|---|---:|---|
| Ambient | `0.03~0.08` | 먼 장식, 보조 눈금 |
| Structural | `0.10~0.18` | 성도 호, 비활성 연결선 |
| Disabled | 약 `0.38` | 읽을 수 있지만 선택되지 않은 항목 |
| Interactive | `0.45~0.75` | 활성 후보, 호버 피드백 |
| Primary | `0.85~1.00` | 선택 항목, 상세 제목 |

애니메이션 중에는 티어 사이 값을 통과할 수 있다. 이 규칙은 정착 상태에 적용한다.

## 14. 카테고리 데이터 구조

도감 렌더링 코드에 카테고리별 문자열과 별자리 좌표를 하드코딩하지 않는다.

```cpp
enum class ArchiveCategory {
    Entities,
    Modules,
    Apex
};

struct ConstellationShape {
    std::vector<Vec2> nodes;
    std::vector<std::pair<int, int>> edges;
    int coreNode;
};

struct ArchiveEntry {
    const wchar_t* id;
    const wchar_t* displayName;
    const wchar_t* summary;
    const wchar_t* classText;
    const wchar_t* statusText;
    const wchar_t* recordType;
    const wchar_t* source;
    ArchiveCategory category;
    Color accent;
    ConstellationShape constellation;
    bool observed;
};
```

`MODULES`가 많아져도 렌더 함수는 같은 데이터 배열을 순회해야 한다. 일반 증강과 디버프 증강의 구분은 데이터의 등급/종류 필드로 처리하며 이동 경로를 별도 하드코딩하지 않는다.

## 15. 최초 로딩 애니메이션

카테고리의 성도 전개 애니메이션은 게임 실행 중 카테고리별 최초 한 번만 재생한다.

```cpp
bool categoryIntroduced[3] = { false, false, false };
```

- 최초 진입: 노드와 연결선이 순차적으로 나타남
- 재진입: 짧은 선택 전환만 적용
- 게임 재시작: 최초 애니메이션 허용 상태로 초기화

목록을 오갈 때마다 긴 연결 애니메이션을 반복하면 탐색 속도와 가독성이 떨어진다.

## 16. 알려진 실패 패턴과 방지 규칙

| 실패 패턴 | 원인 | 방지 규칙 |
|---|---|---|
| 항목 이동 시 별자리가 반대 방향으로 튐 | 비정규화 각도 또는 이중 보간 | 최단 각도 차이 하나만 보간 |
| 호버할 때 별자리 위치가 밀림 | 텍스트 슬라이드 값을 별자리 X에 공유 | 별자리와 텍스트 앵커 분리 |

| 휠 두 번에 한 항목 이동 | 델타 누적 임계값 오류 | OS 휠 노치 정규화 후 1노치=1요청 |
| 복귀 시 화면 플래시 | 딤 또는 패널 플래그 조기 해제 | 마지막 렌더 프레임 후 상태 해제 |

| 리스트가 사라진 것처럼 보임 | 비활성 알파가 Structural 수준 | 비활성 텍스트는 Disabled 수준 유지 |

## 17. 구현 단계

1. 인라인 상태와 진입/복귀 입력 잠금을 확정한다.
2. 루트 메뉴를 공통 메인 메뉴 명령 컴포넌트로 통일한다.
3. 카테고리 및 항목 데이터를 렌더 코드에서 분리한다.
4. 원형 인덱스와 최단 경로 회전 로직을 구현한다.
5. 소형 별자리의 좌표를 텍스트 애니메이션에서 분리한다.
6. 우측 성도와 상세 정보 좌표를 고정한다.
7. 우측 상세 영역에 검은색/보라색 CircleTexture 두 장을 배치한다.
8. 휠, 드래그, 키보드와 복귀 입력을 연결한다.
9. 항목 갱신 및 짧은 디크립팅 연출을 적용한다.
10. 흰색·검은색·컬러 배경에서 가시성을 검증한다.

## 18. 검증 체크리스트

### 기능

- [ ] 메인 메뉴에서 별도 블랙 페이드 없이 진입한다.
- [ ] 진입 중 클릭과 휠 입력이 무시된다.
- [ ] `BACK`, `ESC`, 우클릭이 같은 역재생 복귀를 실행한다.
- [ ] 카테고리 변경 시 올바른 목록과 색상이 적용된다.
- [ ] 한 번의 휠 입력으로 한 항목 이동 요청이 발생한다.
- [ ] 드래그 종료 후 가장 가까운 항목에 정착한다.
- [ ] 마지막 항목과 첫 항목 사이 이동이 자연스럽다.
- [ ] 일반 증강과 디버프 증강 사이 이동이 최단 경로다.

### 시각

- [ ] ONEDOW 로고가 하위 화면에서 사라진다.
- [ ] 거대 성도는 우측 화면 밖으로 일부 잘려 보인다.
- [ ] 소형 별자리가 성도를 감싸며 목록 텍스트와 겹치지 않는다.
- [ ] 호버 슬라이드가 별자리 위치를 움직이지 않는다.
- [ ] 저등급과 고등급 별자리 복잡도가 구분된다.
- [ ] 목록 별자리 노드의 CircleTexture가 해당 색상으로 보인다.
- [ ] 우측 상세 정보 뒤에 검은 대형 CircleTexture가 보인다.
- [ ] 그 위에 더 작은 보라색 CircleTexture가 초점을 만든다.
- [ ] 대형 텍스처가 상세 텍스트 앞을 덮지 않는다.
- [ ] 비활성 텍스트도 읽을 수 있다.

### 배경 대응

- [ ] 흰 배경에서 흰 텍스트와 성도 선이 사라지지 않는다.
- [ ] 검은 배경에서 검은 후면 텍스처의 경계가 사각형처럼 드러나지 않는다.
- [ ] 컬러 배경에서 상세 정보가 배경 이미지와 섞이지 않는다.
- [ ] 사용자 배경 딤 설정을 껐다 켜도 최소 가독성이 유지된다.

### 안정성

- [ ] 빠른 휠 입력에도 방향이 역전되거나 순간 이동하지 않는다.
- [ ] 카테고리 연타 시 동시에 두 목록이 렌더되지 않는다.
- [ ] 복귀 직전 한 프레임 플래시가 없다.
- [ ] 화면 비율 변경 시 상세 정보가 화면 밖으로 나가지 않는다.
- [ ] 항목 수가 0개 또는 1개인 카테고리에서도 나눗셈 오류가 없다.

## 19. 고정 결정과 조정 가능 값

### 고정 결정

- 메인 메뉴 인라인 확장 구조
- `ENTITIES / MODULES / APEX / BACK` 루트 메뉴
- 우측 끝에 걸친 거대한 원형 성도
- 목록 별자리와 텍스트 좌표 분리
- 최단 경로 원형 이동
- 상세 정보는 성도 내부 우측 중앙
- 우측 상세 영역에 실제 CircleTexture 두 장 사용
- 목록 별자리 광원은 해당 별자리 색상 사용
- `MODULES` 상세 정보에서 구매 및 비용 정보 제거

### 조정 가능 값

- 성도 중심 X/Y와 반지름
- 항목 각도 간격 및 화면 표시 개수
- 휠 감도, 최대 각속도, 감쇠 계수
- 소형 별자리 크기와 연결선 길이
- 검은색/보라색 CircleTexture 크기와 알파
- 비활성 텍스트 알파
- 디크립팅 효과의 세부 문자와 스캔 속도

조정 가능 값은 한곳의 레이아웃/스타일 상수로 모아야 한다. 렌더 함수 곳곳에 숫자를 분산시키면 이후 위치 조정 시 다시 항목별 불일치가 발생한다.
