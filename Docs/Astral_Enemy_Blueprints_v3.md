# Astral Enemy Blueprints v3.0

## 0. 이번 개편의 기준

v1·v2의 별자리 그래프 언어(코어 + 노드 + 연결선)를 유지하면서, 두 최상위 적을 다시 정의한다.

| 내부 ID | 이전 역할 | v3 역할 | 티어 |
| --- | --- | --- | --- |
| `QUASAR` | 양방향 빔 저격형 (2.5티어) | 양방향 빔 저격형, **4티어로 승격** | 4 |
| `GENESIS` | ROTOR 소환형 (양방향 레인) | **SWARM 투척형 발사대** | 4 |
| `REGULUS` | 보호막 링크 지원형 (육각 외장 + 육각 보호막) | 보호막 링크 지원형, **방패 문장** 본체 + 곡면 판 보호막 + 아군 모서리 괄호 | 2.5 |
| `MAGNETAR` | 탄 흡수 방어형 (칼날 바람개비 → 마름모+자기력선) | 탄 흡수 방어형, 항상 보이는 **필드 코일** + 코어의 **극 셀**로 스택 표시 | 3 |

공통 원칙:

- 날카로운 **구조적 모서리**(다각형 꼭짓점)는 유지한다. 바깥으로 튀어나오는 **가시·칼날형 돌기**는 쓰지 않는다.
- 티어가 높을수록 층이 많고 선이 얇으며, 흰색 강조를 쓴다. 요소를 늘리기보다 층별 속도 차이로 깊이를 만든다.
- 새로운 파티클 시스템은 추가하지 않는다. 모든 연출은 기존 선·원·노드 프리미티브로 만든다.

## 1. `QUASAR` — 4티어 빔 저격형

### 1.1 4티어 근거

- 화면 전체를 가로지르는 6000px 빔은 게임에서 가장 눈에 띄고, 플레이어가 가장 의식하는 위협이다.
- 스폰 규칙상 **동시 최대 2마리**, 45초 이후 등장, 등장 확률 5%(240초 이후 8%)로 희소하다.
  희소한 만큼 높은 디테일이 화면을 어지럽히지 않으며, 동시 2마리 제한은 4티어 위상을 뒷받침한다.
- 충돌 우선순위(`CollisionTier`)를 3에서 4로 올린다.

### 1.2 구조: 자전하는 셸과 조준하는 코어

두 계층은 **서로 닿지 않는다.** 연결선 없이 축받이 링 하나로만 분리해 별개의 부품으로 읽히게 한다.

| 층 | 구성 | 크기(base 기준) | 회전 기준 |
| --- | --- | --- | --- |
| L1 원반 셸 | 앞쪽 밝은 호 + 뒤쪽 얇고 어두운 호(깊이), 바깥 헤일로 타원 1겹, 원반 위 파편 노드 4개 | 장축 1.45 / 단축 대기 0.95 → 발사 0.45 | `quasarVisualAngle` 자전 + 세차 |
| L2 축받이 링 | 얇은 실선 원 1개 | 반경 0.74 | 셸 반대 방향 저속 회전 |
| L3 구속 코어 | 거의 정사각에 가까운 각진 다이아(길이 0.56, 폭 0.44), 구속 클램프 4개, 불안정 코어 | 클램프 반경 0.52 → 0.66 | `quasarAimX/Y` 조준축 고정 |
| L4 극 제트 | 흰 심선 + 본색 외피 | 길이 0 → 1.0 | 조준축 |

- 크기: `sizeScale` 3.15 → **3.4**. 시야 원 반경 배율도 함께 키운다.
- 파편 노드는 안쪽일수록 빠르게 돌아 케플러식 깊이를 준다.

### 1.3 실루엣: 길쭉함 제거

이전 모델이 길쭉해 보인 원인은 납작한 원반(약 3:1), 상시 노출 극 제트, 축 방향으로 긴 코어였다.

- **대기 중 실루엣은 원에 가깝게** 한다. 원반 비율 약 1.5:1, 제트 숨김, 코어는 정사각에 가까운 다이아.
- **길쭉해지는 순간 = 발사 예고**가 되도록 한다. 충전 중에만 원반이 납작해지고, 코어 다이아가 축 방향으로
  늘어나며(길이 0.56 → 0.76), 제트가 자란다.

### 1.4 불안정한 핵심 코어

"당장이라도 레이저가 나올 것 같은" 긴장은 **규칙적이지 않은 움직임**에서 만든다. 단일 사인 맥동은 쓰지 않는다.

| 요소 | 연출 | 충전에 따른 변화 |
| --- | --- | --- |
| 불규칙 깜빡임 | 주파수가 서로 소인 사인 2~3개를 합성해 밝기가 박자 없이 튐 | 진폭·속도 증가 |
| 코어 떨림 | 흰 중심점이 1~2px 무작위 오프셋. 바깥 광륜은 고정 | 떨림 폭 증가 |
| 구속 클램프 | 코어를 붙잡는 짧은 꺾쇠 4개가 미세하게 떨림 | 충전 끝에 바깥으로 밀려나며 열림 |
| 누설 스파크 | 코어에서 조준축 방향으로 짧은 지그재그 선이 간헐적으로 튐 (MAGNETAR 번개와 같은 그리기 방식) | 빈도 증가, 발사 직전엔 거의 상시 |
| 과충전 테두리 | 코어 테두리가 고르게 맥동하지 않고 한쪽씩 부풂 | 발사 순간 빔으로 이어지며 터짐 |

대기 중에도 불안정은 **약하게 계속 보인다.** 쉬고 있어도 언제든 쏠 수 있다는 긴장을 유지한다.

### 1.5 상태별 연출

| 상태 (시간) | 셸 (L1·L2) | 코어 (L3·L4) |
| --- | --- | --- |
| 대기 (3.2초) | 기본 속도 자전, 원반 둥글게 | 불안정 약하게, 클램프 닫힘, 제트 없음 |
| 탐색 (레인 정렬까지) | 기본 속도 유지 | 코어가 플레이어 쪽으로 축을 돌림, 극 노드 점등, 기존 레인 예고선 유지 |
| 충전 (0.55초) | 자전 3배, 원반 납작·밝아짐, 링 밝아짐 | 다이아 축 방향 연장, 클램프 열림, 누설 스파크 급증, 제트 성장 |
| 발사 (빔 확장 0.7초) | 3배 속도로 빔을 가로지르며 계속 자전 | 코어 흰색, 빔의 뿌리. 기존 방출 링 유지 |
| 회복 (1.4초) | 1.4초 동안 기본 속도로 감속, 원반 다시 둥글게 | 클램프 닫힘, 제트 소멸, 불안정 약하게 |

### 1.6 사망 연출

파편 노드가 접선 방향으로 튕겨 나가고, 축받이 링이 조각나고, 코어가 마지막에 수축하며 한 번 번쩍인다.
사망 연출은 조준축이 아니라 각 층의 실제 각도를 그대로 쓴다(축 튐 없음).

### 1.7 색

셸은 기존 파랑, 코어·제트·클램프는 흰색 계열. 발사 순간에만 최대 밝기. 새 강조색은 추가하지 않는다.

### 1.8 게임플레이 영향

로직 변경 없음. 기존 `quasarVisualAngle`(셸 기울기)과 `quasarAimX/Y`(코어)를 각 층에 연결하고,
셸 자전용 `quasarShellSpin`(기본 2.2 rad/s, 열기에 따라 1~3배속)을 추가했고, 원반 세차 속도는 0.24 rad/s다.
바뀐 수치는 `sizeScale` 3.15 → 3.4, `CollisionTier` 3 → 4뿐이다.
크기 증가로 피격 판정과 접촉 범위도 약 8% 커진다.

## 2. `GENESIS` — SWARM 투척 발사대

### 2.1 역할 변경

이전 구조(양쪽 레인으로 ROTOR 소환)는 대칭 구조를 강제해 어떤 디자인도 "양쪽 문" 형태로 수렴했다.
v3에서는 **플레이어를 향해 SWARM을 직접 던지는 발사대**로 바꾼다. 앞뒤가 있는 비대칭 실루엣이 자연스럽게 나온다.

### 2.2 게임플레이 규칙

| # | 규칙 |
| --- | --- |
| 1 | 비행 중인 SWARM이 플레이어에 맞으면 SWARM은 즉시 사라지고 플레이어는 **10 피해**를 받는다. |
| 2 | 비행 중인 SWARM은 플레이어 탄으로 **격추할 수 있다.** |
| 3 | 착지 지점에서 **ANTARES 기절 방식**으로 잠시 멈춘 뒤 일반 SWARM처럼 추적한다. |
| 4 | **6초마다** 한 번 공격하며, 한 번에 **2~3마리**를 던진다. |
| 5 | 예고 조준선과 동시에 코어에서 SWARM이 생산되는 **빨간색 연출**을 보여준다. |
| 6 | GENESIS의 색은 SWARM과 같은 계열로 맞춘다. |

### 2.3 공격 주기 (6초)

| 구간 | 시간 | 내용 |
| --- | --- | --- |
| 추적 | 0.0 ~ 4.6초 | 천천히 표류하며 선체 정면을 플레이어 쪽으로 돌린다(회전 속도 제한, 옆으로 피할 여지) |
| 조준 | 4.6 ~ 5.4초 (0.8초) | 조준 방향과 착지 지점이 고정되고, 발사 예정 수만큼 조준선이 나타나 점점 밝아진다 |
| 투척 | 5.4 ~ 5.8초 | 0.16초 간격으로 순차 발사. 각 SWARM의 착지 지점은 매번 무작위 |
| 회복 | 5.8 ~ 6.0초 | 포구가 닫히고 약실이 어두워진다 |

- 예고 시간 0.8초로, 회피 가능한 최소 예고(0.5초)보다 길게 잡는다.
- 투척 수 2/3 선택: 생존 시간에 따라 늘린다(예: 4분 이후 3마리). 수치는 밸런스 단계에서 확정한다.

### 2.4 비행 중인 SWARM (투척체)

| 항목 | 값(초안) | 비고 |
| --- | --- | --- |
| 목표 지점 | 조준 고정 시점의 플레이어 위치 기준 반경 250px 원 안의 무작위 지점 (SWARM마다 따로) | 사거리 제한 없음. 조준선이 실제 착지 지점을 그대로 보여줌 |
| 비행 속도 | 전체 거리 기준 0~60% 1400 px/s → 60~80% 1100 px/s → 80~100% 600 px/s | 빠르게 출발해 착지 직전 감속. 600px 거리 비행 시간 약 0.57초 |
| 플레이어 충돌 | 10 피해 후 즉시 소멸 (규칙 1) | 일반 접촉 피해는 비행 중 적용하지 않음 |
| 격추 | SWARM HP 그대로, 탄에 맞으면 사망 처리 (규칙 2) | 처치 보상은 일반 SWARM과 동일 |
| 외형 | 기존 SWARM 삼각형 + 진행 방향 반대쪽 짧은 꼬리선 2개, 비행 중 크기 1.15배 | 날아오는 위협임을 구분 |

### 2.5 착지와 기절

- 목표 지점에 도착하면 **ANTARES 기절 방식**을 그대로 쓴다: 몸체 프레임이 흔들리다 잦아들고 코어가 깜빡인다.
- 기절 시간은 ANTARES와 같은 **0.6초**에서 시작해 조정한다. 기절 중에는 접촉 피해를 주지 않는 것을 권장한다.
- 기절이 끝나면 일반 SWARM 추적으로 전환한다.

### 2.6 외형: 발사대

```
        ┌─── 막힌 후면 선체 ───┐
        │                      │
        │   ▲ 바깥 삼각        │
        │  ▲▼▲ 내접 역삼각     │ ══ 발사 레일 ══▶ 포구 (플레이어 방향)
        │                      │
        └──────────────────────┘
```

- **선체**: 기존 육각 선체를 유지하되, **정면 한 변만 포구로 열린다.** 나머지 다섯 변은 막힌 이중 벽.
  포구 양옆의 도킹 모듈 2개가 발사 레일 역할을 한다. 선체 전체가 플레이어를 향해 회전한다.
- **코어 = 약실**: 바깥 삼각 안에 내접 역삼각을 넣으면 바깥 삼각이 4칸(모서리 삼각 3칸 + 중앙 역삼각 1칸)으로 나뉜다.
  - **모서리 삼각 3칸이 SWARM 약실**이다. SWARM 자체가 삼각형이므로 칸 하나가 곧 SWARM 한 마리로 읽힌다.
  - 이번 공격에서 던질 수(2 또는 3)만큼 칸이 차오른다.
  - 중앙 역삼각은 발사 장치이며, 한 꼭짓점이 항상 포구를 가리킨다.
- **두 삼각은 겹쳐서 육망성을 만들지 않는다.** 역삼각 꼭짓점은 바깥 삼각의 변 중앙에 닿는다.
  다만 정지한 내접 구조는 특정 상징 도형처럼 보일 수 있으므로, 약실이 차는 동안 바깥 삼각을 천천히 회전시켜 정지 도형 인상을 피한다.

### 2.7 빨간색 생산 연출 (규칙 5)

| 시점 | 약실(코어) | 조준선 |
| --- | --- | --- |
| 생산 시작 | 첫 칸이 테두리부터 빨갛게 채워짐 | 첫 조준선이 가늘고 옅은 빨간 실선으로 나타나 점점 굵고 진해짐 |
| 생산 중 | **투척 중을 제외한 모든 상태(회복·추적·조준)에서** 칸이 하나씩 차오르며, 조준이 끝나는 순간 정확히 가득 참. 차오른 칸은 불규칙하게 깜빡임 | 조준 고정 후 찬 칸마다 조준선이 표시됨 |
| 발사 직전 | 모든 칸 최대 밝기, 중앙 역삼각 흰색 | 실선으로 고정 |
| 투척 | 칸이 하나씩 비며, 비는 순간 SWARM이 포구에서 튀어나감 | 발사된 선부터 사라짐 |

- 칸 하나 = 조준선 하나 = SWARM 한 마리로 1:1 대응시켜 "몇 마리가 날아올지"를 미리 읽게 한다.

### 2.8 색 (규칙 6)

- GENESIS 본색을 SWARM(`0.55, 0.00, 0.00`)과 같은 짙은 적색 계열로 바꾼다. 제안값: 선체 `0.70, 0.08, 0.12`, 약실 생산 `1.00, 0.24, 0.20`.
- **ANTARES(진홍 `#E8463A`)와의 구분**: ANTARES는 주황빛 진홍, GENESIS·SWARM은 검붉은 혈적색으로 명도·채도를 나눈다.
  GENESIS는 크기와 육각 선체 실루엣으로도 구분된다.
- 이 변경으로 v2 문서의 GIMBAL 초록/GENESIS 초록 겹침 문제는 자동으로 해소된다.

### 2.9 이동과 배치

- 크기: `sizeScale` 1.9 (v2의 2.2에서 축소).

- 기존처럼 스폰 앵커 주변을 느리게 표류한다(`speed` ×0.35). 공격 중(생산~투척)에는 정지한다.
- 화면 가장자리 제한(`ConstrainGenesisToViewport`)은 유지한다.

### 2.10 사망 연출

약실에 차 있던 칸이 있으면 그 수만큼 빨간 삼각 파편이 튀고, 선체는 6방향으로 흩어진다.
약실의 SWARM은 사망 시 생성하지 않는다(보상 중복 방지).

### 2.11 확정 사항

## 3. `MAGNETAR` — 필드 코일

### 3.1 문제

MAGNETAR는 반경 145px 필드에 들어온 플레이어 탄을 최대 8발까지 막고, 초당 0.3발씩 재충전한다.
기존 외형은 이 역할을 전달하지 못했다.

- 필드 경계가 옅은 짧은 호 4개뿐이라 범위가 보이지 않는다.
- 남은 방어 횟수가 마름모 변 위의 작은 눈금이라 전투 중 읽히지 않는다.
- 자기력선 루프는 예쁘지만 "탄을 막는다"는 정보를 주지 않는다.
- 3티어인데 `sizeScale` 1.45로 다른 상위 몹보다 훨씬 작다.

### 3.2 방향: 필드는 항상, 스택은 코어 주변에

- **필드**: 스택이 1 이상이면 남은 개수와 관계없이 반경 145px 경계를 **항상 온전한 모습**으로 보여준다.
  스택이 0이 되면 필드가 사라지고, 1개라도 재충전되면 다시 나타난다. 필드는 개수를 세는 장치가 아니다.
- **스택**: 코어 본체 주변의 **극 셀**로 표시한다. 자석 축의 양 극 끝에 4칸씩, 모두 8칸이 쌓여 있다.

### 3.3 구성 요소

| # | 요소 | 디자인 |
| --- | --- | --- |
| 1 | 필드 코일 | 반경 145px의 이중 고리(바깥 굵은 선 + 안쪽 얇은 선). 조각으로 나누지 않는다 |
| 2 | 축 클램프 | 필드 고리 위, 자석 축(N·S)과 옆 축에 짧은 각진 눈금 4개. 고리가 본체 방향과 함께 돈다 |
| 3 | 자속 흐름 점 | 필드 고리 위를 흐르는 점. 흡수할 때 빨라진다 |
| 4 | 2겹 마름모 + 전기자 막대 | 본체. N극 끝이 늘 플레이어를 향한다 |
| 5 | 극 셀 8칸 (스택) | 양 극 끝 바깥으로 4칸씩 쌓인 갈매기꼴 셀. 극에서 멀수록 좁아진다. 켜진 셀은 밝은 크림색, 빈 셀은 회색 가는 선. 배터리처럼 바로 셀 수 있다 |

### 3.4 상태 연출

| 상태 | 필드 | 극 셀 / 본체 |
| --- | --- | --- |
| 스택 8 | 표시 | 8칸 모두 점등 |
| 흡수 | 탄이 들어온 지점이 번쩍이고, 탄이 경계를 따라 휘어 빨려 들어감 | 가장 바깥쪽 켜진 셀이 하얗게 터지며 꺼지고, 그 셀에서 흡수 지점으로 번개가 튐. N극과 S극 셀이 번갈아 줄어 좌우 균형 유지 |
| 재충전 | 표시 | 가장 안쪽 빈 셀부터 하나씩 다시 켜짐 (초당 0.3칸) |
| 스택 1 | **그대로 표시** | 셀 1칸만 점등 |
| 스택 0 | **사라짐** | 셀 모두 회색, 안쪽 마름모와 코어가 붉게 노출 = 지금이 공격 타이밍 |
| 0 → 1 | 필드가 본체에서 바깥으로 펼쳐지며 다시 나타남 | 셀 1칸 점등 |

### 3.4.1 검토한 스택 표시 후보

| 후보 | 판단 |
| --- | --- |
| A. 궤도 결정 8개 (본체 둘레를 도는 작은 마름모) | 계속 회전해서 전투 중 세기 어려움 |
| **B. 극 셀 (채택 추천)** | 일렬로 쌓여 바로 셀 수 있고, 자석 축 방향성과 맞물림 |
| C. 안쪽 게이지 링 | 필드 코일과 모양이 겹쳐 두 고리가 헷갈림 |

### 3.5 수치·규칙 (확정)

| 항목 | 추천 |
| --- | --- |
| 꺼지는 셀 | 가장 바깥쪽 켜진 셀부터, N극과 S극 번갈아 |
| 크기 | `sizeScale` 1.45 → 1.8 (피격 판정도 함께 커짐) |
| 재충전 | 초당 0.3조각 유지 (8조각 약 27초) |

## 3A. `REGULUS` — 방패 문장

### 3A.1 문제

- 자기 보호막과 아군에게 준 보호막이 같은 육각 프레임이라 REGULUS가 구분되지 않았다.
- GRAVIS·GENESIS도 육각이라 육각 보호막이 겹치며 화면에 육각형이 과도했다.
- 링크 빔이 3겹 굵은 빔이라 링크가 여러 개면 복잡했다.

### 3A.2 디자인

링크 슬롯(남은 링크 수)은 표시하지 않는다.

| 요소 | 디자인 |
| --- | --- |
| 본체 | 연 모양 방패판 4장이 십자로 모인 문장. **판 끝을 평평하게 잘라** 가시처럼 읽히지 않게 한다. 가운데 정사각 심장 |
| 자기 보호막 | 곡면 판 4장(육각 아님). 남은 양만큼 밝기, 피격 시 번쩍임. 깨지면 어둡고 가는 실선, 재생 8초 동안 점점 굵고 밝아짐 |
| 아군 보호막 | 아군 크기에 맞춘 **모서리 괄호 4개** (점 없음). 남은 양만큼 밝기, 피격 시 번쩍임. 괄호 반폭(× base): ROTOR 1.55 · SWARM 1.30 · GIMBAL 1.75 · GRAVIS 1.55 · QUASAR 1.85 · ANTARES 1.85 · MAGNETAR 2.35 · GENESIS 2.85 · SCOPE 1.70 (스모크 `SHIELD` 단계로 실루엣과 겹치지 않게 맞춤) |
| 보호막 탄 | 연결선 없음. 1초마다 반경 **500px** 안에서 **완전 무작위**로 고른 아군 하나에게 **투사체 없는 즉발 직선 레이저**를 쏜다. 쏘는 순간 보호막이 생기고, 레이저 빛줄기는 0.25초 동안 번쩍였다 사라진다. 이후 아무것도 이어지지 않는다 |
| 보호막 생성 연출 | 받는 몹 주변에 얼음빛 파편 14개가 튀고(기존 적 파티클 사용), 괄호가 1.6배 크기에서 0.25초 동안 제자리로 조여들며 밝게 빛난다 |
| 색·크기 | 얼음빛 청백색 `#B8EFFF`, `sizeScale` 1.5 유지 |

| 회전 | 자기 보호막 곡면 판과 아군 괄호가 **같은 박자**(초당 0.9 rad, 약 7초에 한 바퀴)로 함께 돈다 |

보호막 수치(REGULUS 기본 HP의 60%), 아군당 1회 제한, 자기 보호막 재생 8초는 유지했다.
기존 링크 방식(동시 8칸, 800px, 높은 티어 우선, 끊기면 3초 재사용)은 보호막 탄 방식으로 대체했고, 받은 보호막은 REGULUS가 죽어도 남는다.
