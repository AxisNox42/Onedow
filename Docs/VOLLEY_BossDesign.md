# VOLLEY.sys 리워크 기획안

작성일: 2026-08-12  
대상: `WiNILL/Entity/Boss/ReloadRunnerBoss.h`  
상태: 초안 / 구현 전 설계안

## 1. 핵심 방향

VOLLEY.sys는 메인 모드 첫 번째 보스다. 따라서 어렵게 압박하는 보스보다, 보스전의 기본 문법을 알려주는 입문형 원거리 보스가 되어야 한다.

핵심 결정:

- 샷건 정체성은 제거한다.
- 라이플은 넓은 산탄 난사가 아니라 좁은 3-4발 버스트로 정리한다.
- 근접 플레이를 주력 답으로 만들지 않는다.
- 원거리 보스성을 위해 수류탄/유탄 계열 범위 공격을 추가한다.
- 쉬움/보통은 읽기 쉬운 패턴 중심으로 구성한다.
- 어려움에서만 유도탄, 가짜 조준선, 강한 조합 패턴을 추가한다.
- 무기 전환은 화면 배경 실루엣과 사운드로 강하게 보여준다.

제외:

- 층, 탑, 층 클리어 구조.
- 비활성 보스와의 설정 연결.
- 화면 전체를 덮는 무작정 탄막.
- 라이플을 샷건처럼 쓰는 공격.
- 단순 체력/탄속/공격력 증가만으로 만든 난이도 차이.

## 2. 보스 개요

```text
이름: VOLLEY.sys
역할: 메인 모드 1번째 보스
전투 타입: 입문형 원거리 화력 보스
핵심 키워드: 조준선, 짧은 연사, 범위 예고, 구역 회피, 재장전 빈틈
전투 길이: 보통 난이도 기준 70-90초
```

플레이어가 배워야 하는 것:

- 조준선이 보이면 선 밖으로 빠진다.
- 라이플 버스트는 짧은 이동으로 피한다.
- 수류탄 표식이 보이면 해당 구역에서 빠진다.
- 미니건 부채꼴은 방향을 읽고 바깥으로 돈다.
- 보스가 재장전하거나 과열되면 짧게 반격한다.

## 3. 현재 문제

현재 VOLLEY는 `SHOTGUN / SNIPER / MACHINEGUN`, `RELOAD_SPRINT`, `EDGE_SALVO`, `ASSAULT`, HP 기반 `phase2 / phase3` 구조를 갖고 있다.

가장 큰 문제는 라이플 역할이어야 할 공격이 샷건성 산탄 난사처럼 보인다는 점이다.

정리할 문제:

- 첫 보스치고 탄의 양이 많아 보인다.
- 라이플, 샷건, 미니건의 차이가 흐려진다.
- 근접 시 샷건/패닉/재장전이 얽혀 전투 의도가 흐려진다.
- 플레이어가 붙어서 때리는 것이 답이라고 오해할 수 있다.
- 페이즈 변화가 새로운 학습보다 단순 강화로 느껴진다.

기획 기준 무기:

```text
SR: Sniper Rifle
RF: Rifle
MG: Minigun
GL: Grenade Launcher / 보조 범위 공격
```

## 4. 페이즈 구조

권장 HP 구간:

```text
Phase 1: 100% - 70%   SR 학습
Phase 2: 70% - 40%    RF + GL 학습
Phase 3: 40% - 0%     MG + 복습
```

### Phase 1 - SR Calibration

목적: 조준선과 보스 빈틈을 학습시킨다.

사용:

- `SR_LOCK`: 긴 조준선 후 고속 단발.
- `RF_TAP`: 약한 2발 견제.
- `RELOAD_STEP`: 짧은 후퇴 후 빈틈.

금지:

- `EDGE_WARNING`
- `ASSAULT`
- `CURVE_MISSILE`
- 강한 `MG_ZONE`
- 넓은 산탄

### Phase 2 - RF Grenadier

목적: 짧은 연사와 범위 예고를 함께 학습시킨다.

사용:

- `RF_BURST`: 3-4발 좁은 라이플 연사.
- `GRENADE_ARC`: 플레이어 위치를 예측해 수류탄 투척.
- `BACKSTEP_GRENADE`: 근접 시 뒤로 빠지며 약한 수류탄.
- `RELOAD_STEP`: 재장전 빈틈.

### Phase 3 - MG Overheat

목적: 구역 장악 패턴과 과열 딜타임을 학습시킨다.

사용:

- `MG_ZONE`: 부채꼴 위험 영역 표시 후 미니건 사격.
- `MG_SWEEP`: 부채꼴이 천천히 회전.
- `OVERHEAT`: MG 종료 후 확정 딜타임.
- `GRENADE_ARC`: 안전지대 이동을 방해하는 단발 범위 공격.

## 5. 주요 패턴

### SR_LOCK

```text
텔레그래프: 플레이어 방향 청록색 조준선
발사: 빠른 고위력 직선탄 1발
대응: 조준선 고정 후 옆으로 회피
```

### RF_BURST

```text
텔레그래프: 총구 점멸
발사: 좁은 각도의 3-4발 버스트
대응: 연사 리듬 사이로 짧게 이동
```

중요:

- 넓게 퍼지는 산탄 금지.
- 한 번에 9발 이상 뿌리는 공격 금지.
- 어려움에서도 넓은 확산보다 짧은 재조준으로 강화한다.

### GRENADE_ARC

```text
텔레그래프: 착탄 위치에 붉은 원 표시
발사: 포물선 수류탄
폭발: 착탄 후 작은 원형 범위 피해
대응: 표식 밖으로 이동
```

역할:

- 원거리 보스성을 강화한다.
- 플레이어가 한 방향 회피만 반복하지 않게 한다.
- 근접 플레이를 직접 처벌하기보다 위치 이동을 유도한다.

### BACKSTEP_GRENADE

```text
조건: 플레이어가 일정 거리 이하로 접근
행동: 보스가 뒤로 빠지며 수류탄 투척
대응: 추격을 멈추고 폭발 범위 밖으로 이동
```

기존 샷건 근접 대응을 대체하는 패턴이다. 피해량보다 밀어내기와 거리 재설정 역할이 중요하다.

### MG_ZONE / OVERHEAT

```text
MG_ZONE:
  노란 부채꼴 경고 후 해당 영역에 미니건 사격.

OVERHEAT:
  MG 종료 후 1.0-1.6초 공격 중지.
```

첫 보스이므로 MG는 압도적인 난사보다 "위험 구역 읽기"에 초점을 둔다. MG 후에는 반드시 `OVERHEAT`가 따라와야 한다.

### PANIC_PULSE

```text
조건: 플레이어가 너무 가까이 접근
텔레그래프: 보스 주변 원형 경고
발동: 약한 원형 충격파
효과: 약한 피해 또는 밀어내기
```

샷건식 즉사 대응 대신 읽을 수 있는 근접 억제 패턴으로 사용한다.

## 6. 어려움 전용 패턴

### CURVE_MISSILE

사용자 제안 반영 패턴.

```text
난이도: 어려움 전용
텔레그래프: 보스 양옆 미사일 포트 점등
발사 방식: 플레이어를 향해 곡선으로 휘는 투사체
발사 간격: 0.8초
발사 횟수: 총 5회
대응: 한 방향으로 계속 도망치지 말고, 유도 각이 꺾이는 타이밍에 방향 전환
```

제한:

- 즉발 완전 추적 금지.
- 회전 각속도 제한.
- 첫 0.3초는 직진성이 강하고 이후 천천히 휜다.
- `MG_ZONE`과 완전 동시 사용 금지.
- 첫 등장 시에는 단독 패턴으로 보여준다.
- `CURVE_MISSILE` 도중에는 수류탄을 던지지 않는다.

### BLANK_ROUND

```text
텔레그래프: 스나이퍼 조준선 2개 표시
발사: 실선 조준선만 실제 탄 발사, 점선은 가짜
대응: 가짜/진짜 시각 규칙 학습
```

보통 이하에는 넣지 않는다.

### MAG_DUMP

```text
텔레그래프: 탄창 아이콘 점멸
발사: 좁은 각도의 빠른 라이플 연사
후딜: 긴 재장전 / 과열
대응: 옆으로 빠진 뒤 후딜에 반격
```

샷건처럼 넓게 퍼지면 안 된다. 총알 수는 많아도 각도는 좁아야 한다.

## 7. 난이도별 구성

### 쉬움

목표: 첫 보스답게 쉽고 명확해야 한다.

사용:

- `SR_LOCK`
- 약한 `RF_TAP`
- 약한 `RF_BURST`
- 단발 `GRENADE_ARC`
- 느린 `MG_ZONE`
- `RELOAD_STEP`
- 약한 `PANIC_PULSE`

제거:

- `CURVE_MISSILE`
- `BLANK_ROUND`
- `MAG_DUMP`
- `EDGE_WARNING`
- `ASSAULT`
- 넓은 산탄
- 무작위 무기 꼬기

### 보통

목표: 정식 패턴 세트를 보여주되, 첫 보스 난이도를 유지한다.

사용:

- `SR_LOCK`
- `RF_BURST`
- `GRENADE_ARC`
- `BACKSTEP_GRENADE`
- `MG_ZONE`
- `OVERHEAT`
- `RELOAD_STEP`
- 약한 `EDGE_WARNING`

제한:

- 동시에 작동하는 위험원은 최대 1-2개.
- `MG_ZONE` 중 수류탄을 던질 경우 착탄 시간을 길게 둔다.
- `ASSAULT`는 보통에서는 빼거나 매우 낮은 빈도로 둔다.

### 어려움

목표: 첫 보스의 기본기를 유지하되, 숙련자에게 읽기 부담을 추가한다.

추가:

- `CURVE_MISSILE`
- `BLANK_ROUND`
- `MAG_DUMP`
- 강화된 `EDGE_WARNING`
- 제한적인 `RELOAD_SPRINT`

제한:

- 탄속과 피해량 증가는 10-15% 선에서 제한한다.
- 위험원은 최대 2개까지만 겹친다.
- `CURVE_MISSILE`은 0.8초마다 5발이라는 고정 리듬을 유지한다.
- 어려움이어도 첫 보스이므로 즉사성 조합은 금지한다.

## 8. 무기 전환 연출 / 오디오

VOLLEY는 무기 전환이 핵심인 보스이므로, 무기가 바뀌는 순간을 화면과 사운드 양쪽에서 강하게 인지시킨다.

기본 흐름:

```text
무기 전환
-> BGM 짧게 덕킹 또는 정지
-> 장전 / 슬라이드 / 회전 / 핀 뽑는 사운드
-> 배경에 거대한 반투명 무기 실루엣 표시
-> 보스 색상과 무기 태그 변경
-> 0.2-0.4초 뒤 다음 패턴 시작
```

배경 실루엣:

```text
SR: 긴 저격총 실루엣 / 조준선
RF: 소총 실루엣 / 탄창 아이콘
MG: 회전 총열 실루엣 / 원형 배럴
GL: 수류탄 또는 유탄 발사기 실루엣
```

권장:

- 실루엣 불투명도는 6-12%.
- 무기 전환 시 0.25-0.45초 크로스페이드.
- 탄막, 수류탄 표식, 조준선을 가리지 않는다.
- 총기 이모티콘은 프로토타입 후보로만 사용한다.
- 실제 구현은 단색 실루엣 또는 픽셀아트풍 아이콘을 권장한다.

오디오:

```text
일반 무기 전환: BGM 볼륨을 0.15-0.30초 동안 35-50%로 낮춤
페이즈 전환: BGM을 0.4-0.8초 거의 정지시키고 전환 사운드 강조
Phase 3 진입: 짧은 무음 후 MG 회전음으로 재진입
CURVE_MISSILE: 락온음, 휘는 추진음, 짧은 경고 비프 5회
```

## 9. 구현 방향

1차 구현:

- 기존 `SHOTGUN`을 `RIFLE` 기획으로 교체한다.
- 라이플 탄 수와 확산각을 크게 줄인다.
- `GRENADE_ARC`를 추가한다.
- 근접 대응을 `PANIC_PULSE` 또는 `BACKSTEP_GRENADE`로 바꾼다.
- 쉬움 난이도에서 `EDGE_WARNING`, `ASSAULT`, 보조 스나이퍼탄을 끈다.
- `MG_ZONE` 후 `OVERHEAT`를 확정으로 준다.

2차 구현:

- 어려움 전용 `CURVE_MISSILE` 추가.
- 어려움 전용 `BLANK_ROUND` 추가.
- 어려움 전용 `MAG_DUMP` 추가.
- HUD 태그를 `SG/SR/MG`에서 `SR/RF/MG/GL` 기준으로 정리한다.
- 무기 전환 배경 실루엣과 사운드 덕킹을 추가한다.

예시 구조:

```cpp
enum class RRWeapon {
    Sniper,
    Rifle,
    Minigun,
    Grenade
};

struct RRPatternRules {
    bool allowEdgeWarning;
    bool allowAssault;
    bool allowBlankRound;
    bool allowCurveMissile;
    bool allowReloadSprint;
    int rifleBurstCount;
    int curveMissileCount;
    float curveMissileInterval;
    float sniperAimMul;
    float grenadeFuseMul;
    float mgWarmupMul;
};
```

## 10. 완료 기준

- 메인 모드 첫 보스답게 쉬움/보통 난이도에서 읽기 쉽다.
- 라이플이 샷건처럼 보이지 않는다.
- 근접해서 계속 때리는 플레이가 최적해가 아니다.
- 수류탄 표식과 조준선의 대응법이 명확하다.
- 보통 난이도에서 `SR`, `RF`, `GL`, `MG` 대표 패턴을 모두 경험한다.
- 어려움 난이도에서 `CURVE_MISSILE`은 0.8초마다 5회 발사되는 고정 리듬으로 작동한다.
- MG 페이즈에는 반드시 확실한 `OVERHEAT` 딜 타이밍이 있다.
- 무기 전환 순간을 소리와 배경 실루엣만으로 구분할 수 있다.
- 사망 원인을 "무엇을 잘못 봤는지" 설명할 수 있다.
