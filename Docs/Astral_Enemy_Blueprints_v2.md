# Astral Enemy Blueprints v2.0

## 0. 이번 개편의 기준

v1에서 확립한 기하학적 실루엣 언어를 유지하면서, 지원형·굴절형·포식형 역할군을 추가한다.
이번 버전의 외형은 천문 장비나 행성의 형태를 직접 묘사하지 않는다. 모든 적은
**중앙 코어 + 별 노드 + 연결선으로 이루어진 하나의 별자리 그래프**로 읽혀야 한다.

새로 추가되는 적들은 세 가지 역할 레이어를 채운다.

1. **지원 레이어**: 단독으로는 위협이 작지만 주변 적에게 오라를 부여해 집단 전체를 강하게 만든다.
2. **굴절·흡수 레이어**: 플레이어의 총알 전략을 직접 방해한다.
3. **포식 레이어**: 전장의 다른 적을 흡수하며 스스로 성장한다.

외형 규칙은 v1의 NodeAnchor 시스템을 그대로 따른다. 새로운 파티클 시스템을 추가하지 않는다.

| 내부 ID      | 역할               | 표시 이름      | 티어  |
| ---------- | ---------------- | ---------- | --- |
| `REGULUS`  | 일회성 보호막 링크 지원형 | `REGULUS`  | 2.5 |
| `ALCOR`    | 속도 증폭 오라 지원형     | `ALCOR`    | 2   |
| `MAGNETAR` | 총알 굴절 방어형        | `MAGNETAR` | 3   |
| `UMBRA`    | 총알 흡수 폭발형        | `UMBRA`    | 3   |
| `COLLAPSE` | 적 포식 성장형 (붕괴 신호)   | `COLLAPSE` | 2→4 |
| `ANTARES`  | 가속 투우형 추적          | `ANTARES`  | 2   |

## 1. 공통 외형 규칙

v1의 `NodeAnchor` 규칙을 그대로 적용한다. 다만 v2의 별자리 적들은 아래의
추가 규칙을 우선한다.

### 1.1 별자리 그래프 규칙

- 모든 적은 역할에 맞는 밝기의 중앙 코어 1개와 고정된 `NodeAnchor[]`를 가진다.
- 실루엣은 닫힌 도형이 아니라 **노드 사이의 연결 구조**로 만든다. 원, 육각형,
  강착 원반처럼 보이는 닫힌 외곽선은 사용하지 않는다.
- 연결선은 기본 0.70~1.15px, 노드는 코어 반경의 0.35~0.70배로 제한한다.
- 한 적이 화면에서 유지하는 별 노드는 최대 8개, 코어에 직접 연결되는 선은 최대
  6개로 제한한다. 작은 화면에서도 토폴로지가 먼저 읽혀야 한다.
- 노드의 위치는 선·후광·중심점·상태 애니메이션이 모두 공유한다. 별도 보정 좌표를
  두지 않는다.
- 별자리의 색은 역할을 나타내고, 상태 변화는 노드 점등 순서와 연결선의 길이·알파로
  표현한다. 새로운 파티클이나 천문 표면 텍스처는 추가하지 않는다.

권장 색상 팔레트는 다음과 같다.

| 적 | 기본색 | 상태 강조색 | 시각적 인상 |
| --- | --- | --- | --- |
| `REGULUS` | 청백색 `#B8EFFF` | 흰색 | 보호 결절망 |
| `ALCOR` | 호박색 `#FFB84D` | 밝은 황색 | 양방향 가속 흐름 |
| `MAGNETAR` | 보라-청색 `#8C7CFF` | 주황색 | 꺾인 편향 결절 |
| `UMBRA` | 먹색-남보라 `#17152E` | 적보라색 | 안쪽으로 접히는 빈자리 |
| `COLLAPSE` | 검정-자주 `#0A0714` | 흰색/적색 | 먹이를 향해 수축하는 그래프 |
| `ANTARES` | 진홍색 `#E8463A` | 경고색 코어 (4단계), 빨강/청록 색수차 (잔상) | 빨라지며 번지는 분절 오각 프레임 |

### 1.2 오라 표현 규칙

지원형·굴절형 적은 영향 범위를 시각적으로 표현해야 한다. 오라는 아래 기준을 따른다.

- 오라 경계는 닫힌 면이나 링이 아니라, 외곽 노드 사이에 생기는 **짧은 보조선 3~5개**로 표시한다.
- 오라가 활성화된 상태에서만 보조선이 나타나고, 비활성 시 즉시 사라진다.
- 오라 범위 안에 있는 아군 적에게는 가느다란 연결선이 잠깐 나타날 수 있으나 항상 코어보다 얇아야 한다.
- 오라 보조선의 알파값은 코어보다 반드시 낮게 유지한다.
- 같은 오라의 보조선은 한 프레임에 최대 2개만 밝힌다. 전장을 그물처럼 덮지 않는다.

### 1.3 중첩 제한 시각 표현

같은 종류의 오라가 여러 개 겹쳐도 효과는 중첩되지 않는다.
이미 오라를 받고 있는 적에게는 연결선을 그리지 않는다.

### 1.4 성장형 적의 크기 단계

`COLLAPSE`는 흡수 횟수에 따라 코어와 별자리의 간격이 단계적으로 줄어든다.
크기 변화와 노드 수축은 부드러운 선형 보간을 사용하며, 순간이동처럼 보이지 않는다.

## 2. 적별 디자인

### 2.1 `REGULUS` — REGULUS (티어 2.5)

**주변 적에게 일회성 보호막을 연결하는 후방 지원체.** 본체는 커진 청백색 에너지 코어와
여섯 갈래 외장 구조로 구성되며, 보호막 링크는 본체와 대상 코어를 직접 잇는다.

#### 별자리 구조

- 중앙에 짙고 작은 청백색 코어 `◉` 1개를 둔다.
- 본체 보호막은 천천히 회전하고 밝기가 호흡하는 분절 육각 방호판 한 겹이다.
- 코어 둘레에는 여섯 갈래 지지대와 외곽 장갑판을 더해 본체의 구조감을 강조한다.
- 보호 대상에는 더 큰 분절 육각 방호판 한 겹을 표시하고, 모서리 결절이 순서 없이 맥동한다.
- 원형 고리와 조준 브라켓은 쓰지 않는다.
- 연결선은 본체와 보호 대상의 코어 중심을 직접 잇는다.

#### 보호막 연결

- 동시에 최대 8개 코어를 연결한다. 높은 티어부터 선택하고, 같은 티어에서는 가까운 대상을 먼저 잇는다.
- `REGULUS`는 연결 대상에서 제외한다. 레굴루스끼리는 보호막을 주지 않는다.
- 연결 범위는 800px이며, 연결 슬롯마다 3초의 독립 재연결 대기시간이 있다.
- 대상 보호막 파괴, 대상 사망/범위 이탈, 본체 사망 시 해당 선을 끊는다.
- 유효한 연결선은 끊김 없는 굵은 빛줄기로 유지되고, 세 개의 빛 맥동이 대상을 향해 흐른다.
- 연결이 끊기면 선은 사라지고 중간 지점에서 작은 빛 파티클을 터뜨린다.
- 공격하지 않으며 무작위 방향으로 천천히 떠돈다.

#### 보호막 체력

- 기본 체력은 SCOPE와 같은 수준(360)이다.
- 본체 보호막은 기본 체력의 0.9배이며, 파괴 후 8초 뒤 전량 재생한다.
- 연결 대상 보호막은 레굴루스 기본 체력의 0.6배로, 몹 종류와 무관하게 같은 고정값이다.
- 보호막은 본체 체력과 별도로 피해를 흡수한다. 보호막을 넘긴 공격의 초과 피해는 본체에 들어간다.
- 대상 몹은 생애 중 보호막을 한 번만 받는다. 파괴된 뒤 다른 레굴루스가 다시 부여할 수 없다.
- 본체 보호막은 대상 보호막보다 1.5배 강하다.
- 보호막 파괴에는 전용 애니메이션 없이 기존 파티클 풀을 사용한다. 대상 보호막은 크게, 연결선 단절은 작게 표현한다.

금지 사항:
- 본체와 대상 보호막을 완전한 원형 고리로 그리지 않는다.
- `REGULUS`끼리 연결하거나 서로 보호막을 부여하지 않는다.
- 대상 보호막을 중첩하거나 재부여하지 않는다.
- 공격 연출을 추가하지 않는다.

### 2.2 `ALCOR` — ALCOR (티어 2)

**주변 적의 이동속도를 끌어올리는 양방향 가속 흐름.** 링을 돌리는 대신,
코어 양쪽의 열린 별자리 스트림이 한 방향으로 밀려가는 모습을 사용한다.

#### 별자리 구조

```text
        L1──L2       R2──R1
             ╲       ╱
                ◉
             ╱       ╲
        L3──L4       R4──R3
```

- 주황빛 코어 1개와 좌·우 위·아래에 각각 2개씩, 총 8개의 가속 노드를 둔다.
- 위쪽 경로 `L1-L2`, `R2-R1`과 아래쪽 경로 `L3-L4`, `R4-R3`는 서로 완전히
  겹치지 않도록 위·아래 높이를 다르게 둔다.
- 각 경로의 바깥쪽 끝이 12~18도 앞서 움직인다. 이 앞쪽 끝이 속도 증가의
  방향성을 담당한다.
- 네 경로는 코어에 직접 연결하지 않고, 안쪽 노드 `L2/L4/R2/R4`만 코어와
  희미하게 연결한다. 완전한 원이나 궤도는 만들지 않는다.

#### 오라 연출

- 비활성 시 네 경로 중 두 개만 희미하게 남긴다.
- 오라 활성 시 네 경로가 같은 방향으로 한 번에 점등되며, 0.35초 동안 노드 간
  간격이 12% 늘어난다.
- 가속 효과를 받는 적 쪽으로 짧은 방향성 선 하나가 0.12초 나타났다가 사라진다.
- 스스로도 빠르게 이동하며 플레이어 주변을 배회하지만, 배회 궤적을 원형으로
  그리지 않는다.

**오라 효과**
- 반경 150px 내 적 이동속도 +45%.
- 여러 ALCOR의 효과는 중첩되지 않으며 가장 높은 값 하나만 적용.

**읽힘**: 주황 코어 + 양쪽의 열린 가속 스트림 + 순차 점등 = 기동 지원체.

금지 사항:
- 닫힌 링을 사용하지 않는다.
- 좌·우 스트림을 하나의 긴 직선으로 합치지 않는다.
- 코어보다 큰 노드 후광을 사용하지 않는다.

### 2.3 `MAGNETAR` — MAGNETAR (티어 3)

**플레이어를 추격하며 전기장 스택을 소모해 탄환을 요격하는 추적형 방어 몹.**

#### 별자리 구조

```text
                 T1
                /
             N1
                ╲
                 ◉──N2──T2
                ╱   ╲
             N4       N3
                ╲     ╱
                 T4  T3
```

- 흰색 코어 1개와 노란색 네 갈래 날개를 둔다. 날개마다 스택 표시 두 개를 두어
  최대 8개의 요격 스택을 실루엣 안에 읽히게 한다.
- 네 날개는 회전하는 동안 같은 방향으로 한 번 꺾여 핀휠을 만든다. 십자처럼 보이지
  않도록 날개 사이에 빈 공간을 남기고, 원형으로 연결하지 않는다.
- 각 날개는 두 개의 직선 세그먼트로 그려 꺾임을 분명히 한다. 별자리 그래프가 보이고,
  `GRAVIS`의 중력선이나 완성된 원형 장치처럼 보이지 않아야 한다.

#### 상태 연출

- 정상: 충전된 스택 표시는 밝게 유지하고, 소모된 스택 표시는 어둡게 둔다.
- 요격: 탄환이 전기장 경계를 통과하면 해당 탄환을 지우고, 전기장과 가장 가까운
  날개 끝에서 요격 지점까지 짧은 섬광을 낸다.
- 재충전: 기본 초당 0.3스택을 회복한다. 주변 360px 안의 티어 2 이상 아군마다
  회복량이 초당 0.3씩 늘며, 최대 초당 1.2스택까지 회복한다.
- 스택이 0이면 요격만 멈춘다. 추격과 접촉 공격은 계속 유지된다.

**요격 메카닉**
- 전기장 반경은 `145px`, 최대 스택은 `8`이다.
- 플레이어 탄환 한 발을 요격할 때마다 스택을 `1` 소모한다. 적 탄환은 영향을 받지 않는다.
- 전기장 안에 티어 2 이상 아군이 있으면 스택 회복 속도가 증가한다.

**읽힘**: 흰색 코어 + 같은 방향으로 꺾인 노란색 네 날개 + 스택 표시 = 탄환 요격형.

금지 사항:
- 네 날개의 꺾임 방향을 서로 다르게 만들지 않는다.
- 날개를 원형으로 연결하거나 스택 표시를 8개보다 많이 늘리지 않는다.
- 스택이 0일 때 요격이 계속되는 것처럼 표현하지 않는다.

### 2.4 `UMBRA` — UMBRA (티어 3)

**총알을 안쪽으로 접어 넣다가 한도를 넘으면 폭발하는 흡수형 별자리.**
블랙홀이나 소용돌이를 그리지 않고, 코어를 향해 끊어진 세 갈래가 접히는 모습으로 표현한다.

#### 별자리 구조

```text
       A────B          E────F
             ╲        ╱
               ◉
                ╲    ╱
                 C──D
```

- 거의 빛나지 않는 남보라색 코어 1개와 3개의 흡수 갈고리를 사용한다.
- 각 갈고리는 바깥 노드 1개와 안쪽 노드 1개로 구성한다. 총 6개 노드이며,
  안쪽 노드는 코어에 닿지 않고 항상 6~10px의 빈틈을 남긴다.
- 세 갈고리는 118°, 238°, 358° 방향에 두되, 동일한 나선으로 연결하지 않는다.
  각 갈고리의 마지막 선분만 코어 쪽으로 향하게 한다.
- 코어는 검지만 얇은 보라색 외곽광만 유지한다. 밝은 링이나 원형 폭발 테두리는
  사용하지 않는다.

#### 상태 연출

- 대기: 세 안쪽 노드가 서로 다른 속도로 4~8px씩 코어에 가까워졌다 돌아온다.
- 흡수 중: 탄환이 들어온 방향의 갈고리만 안쪽 노드부터 한 단계씩 접힌다.
- 폭발 직전: 세 안쪽 노드가 코어 주변에서 떨리고, 코어의 외곽광이 적보라색으로
  넓어진다.
- 폭발: 세 갈고리가 0.16초 동안 코어 쪽으로 접힌 뒤, 코어 중심에서 짧은 적색
  펄스가 나온다. 폭발 반경은 흡수량에 비례한다.
- 재충전 중: 코어와 안쪽 노드만 남기고 바깥 노드는 숨긴다.

**흡수 메카닉**
- `absorbLimit = 20발` (총알 관통력·크기에 따라 가중치 다름)
- 한도 초과 시 즉시 폭발 후 3초 재충전
- 폭발 반경: 흡수된 총알 수 × 5px (최대 200px)

**읽힘**: 어두운 코어 + 빈틈을 남긴 세 갈고리 별자리 = 탄환을 접어 넣는 흡수체.

금지 사항:
- 코어를 밝게 만들지 않는다 (폭발 직전 적보라색 외곽광 제외).
- 세 갈고리를 하나의 연속된 나선이나 링으로 연결하지 않는다.
- 폭발 반경을 항상 최대로 고정하지 않는다.

### 2.5 `COLLAPSE` — COLLAPSE (티어 2→4)

**주변의 낮은 티어 적을 먹으며 별자리 자체가 수축하고 성장하는 포식형 붕괴 신호.**

처음 등장 시에는 작고 조용하지만, 전장에 오래 방치할수록 제거하기 어려워진다.

#### 별자리 구조

```text
             A──B
                ╲
      C──D ───── ◉ ───── F──E
```

- 중앙 코어는 거의 검정인 `Null Core`로 둔다. 코어 주변에 밝은 원형 테두리를
  두지 않고, 중심이 비어 보이는 것이 정체성이다.
- 코어 주변에 3개의 포식 가지를 둔다. 각 가지는 바깥 노드와 안쪽 노드로 구성하며,
  총 6개 노드까지만 사용한다. `B`, `D`, `F`는 코어에 가까운 안쪽 노드다.
- 바깥 노드와 안쪽 노드 사이에는 선을 하나만 둔다. 안쪽 노드와 코어 사이에는
  흡수 중일 때만 짧은 연결선이 생긴다.
- `COLLAPSE`의 실루엣은 밝은 링이 아니라 **노드 간격이 줄어드는 그래프**다.

#### 상태 연출

- 대기: 3개의 포식 가지가 낮은 알파로 고정되고, 코어는 거의 빛나지 않는다.
- 포식 당기는 중: 먹이 적과 가장 가까운 가지 하나에만 얇은 연결선이 생긴다.
  먹이가 가까워질수록 해당 가지의 안쪽 노드가 코어 쪽으로 이동한다.
- 흡수 완료: 대상 적이 사라지는 순간 해당 가지의 두 노드가 코어 주변으로
  0.22초 동안 수축한다.
- 단계 성장: 코어 반경과 노드 크기가 동시에 0.8초 동안 보간된다. 이미 수축한
  가지는 다시 펼쳐지지 않는다.
- 최대 단계: 포식 가지 3개가 코어 가까이에 짧은 세 갈래로 남고, 더 이상 성장하지 않는다.

#### 크기 단계

| 흡수 횟수 | 단계   | 코어 반경 | 별자리 확산 반경 | 포식 가지 길이 | 흡수 반경 |
| --- | --- | --- | --- | --- | --- |
| 0     | 1단계  | 14px  | 54px | 28px | 80px  |
| 3     | 2단계  | 20px  | 46px | 24px | 120px |
| 6     | 3단계  | 28px  | 38px | 19px | 160px |
| 10    | 4단계 (최대) | 38px  | 30px | 14px | 200px |

단계 사이의 크기 변화는 0.8초 선형 보간으로 처리한다.

#### 포식 메카닉

- 흡수 반경 내에 자신보다 낮은 티어의 적이 들어오면 천천히 당겨진다.
- 당겨지는 적은 이동 속도의 일부가 COLLAPSE 방향으로 치환된다.
- 흡수 완료 시 (거리 < 10px): 해당 적 즉시 제거, 흡수 횟수 +1, **XP 지급 없음**.
- 4단계 도달 후에는 흡수가 멈추고 최대 크기를 유지한다.
- COLLAPSE 자신은 이동하지 않는다. 위치가 고정된 위험 구역으로 설계한다.

#### 전략적 의도

플레이어는 두 가지 선택을 강요받는다.

1. 주변 잡몹을 먼저 처치해 COLLAPSE의 먹이를 차단한다.
2. COLLAPSE를 우선 제거해 성장 자체를 막는다.

흡수된 적은 XP를 주지 않으므로 방치는 단기적으로는 전장이 정리되는 것처럼 보이지만, 장기적으로 더 강한 COLLAPSE와 XP 손실이라는 이중 손해를 낳는다.

**읽힘**: 빛을 내지 않는 코어 + 코어 쪽으로 수축하는 포식 가지 = 방치 불가 포식형 위협.

금지 사항:
- 코어 외곽에 밝은 링이나 원형 테두리를 만들지 않는다.
- 포식 가지를 4개 이상 사용하지 않는다.
- 이동 능력을 부여하지 않는다.
- 최대 단계 이후에도 계속 성장하도록 만들지 않는다.
- 플레이어를 직접 흡수하지 않는다.

### 2.6 `ANTARES` — ANTARES (티어 2)

**쫓아올수록 빨라지고 회전이 거세지다가, 결국 플레이어를 지나쳐 버리는 투우형 추적 신호.**
"누구보다 먼저 너를 죽이러 온다"는 인상을 이동·회전·잔상 세 가지가 동시에 쌓아 올린다.
별도의 돌진 동작은 없다. 가속하며 쫓아오는 것 자체가 돌진이다.

#### 별자리 구조

```text
              V1
            ╱    ╲
         V5        V2
          │   ◉    │
          V4 ──── V3
```

- 진홍색 코어 1개와 오각형 꼭짓점 노드 5개를 사용한다. 프레임 외접 반경은 `ROTOR`의
  약 2배로, 화면에서 확실히 큰 몹으로 읽혀야 한다.
- 오각 프레임은 **꼭짓점마다 틈을 둔 분절 프레임**이다. 다섯 변은 서로 닿지 않으며,
  닫힌 오각형 외곽선으로 그리지 않는다.
- 코어는 프레임 크기에 비해 작게 유지해 속이 빈 기계 프레임처럼 보이게 한다.
- 별 오각형(펜타그램) 연결은 사용하지 않는다. 투사체·표창처럼 읽힌다.

#### 투우 구조

추적하는 동안 이동 속도가 계속 오르고, 프레임 회전도 속도에 비례해 빨라진다.
대신 빨라질수록 방향을 잘 틀지 못한다. 그래서 속도가 오를수록 **플레이어를 빗맞히고
지나칠 확률**이 커지고, 지나치는 순간 1단계로 떨어진다.

- 이동 속도: 60 px/s에서 시작해 초당 128 px/s씩 올라 약 5초 뒤 최고 700 px/s에 이른다.
- 선회 속도: 속도에 반비례해 180°/s(최저 속도) → 40°/s(최고 속도)로 줄어든다.
- 프레임 회전: 속도에 비례해 30°/s → 540°/s로 늘어난다.
- 단계는 현재 속도로 정한다.

| 단계 | 이동 속도 | 잔상 |
| --- | --- | --- |
| 1 | 60~200 px/s | 0~2 |
| 2 | 200~350 px/s | 2~3 |
| 3 | 350~500 px/s | 3~5 |
| 4 | 500~700 px/s | 5~6 + 색수차 |

#### 지나침, 감속, 휴식

- **지나침 판정** (속도 500 px/s 이상, 4단계에서만):
  - 320px 안에 있던 플레이어가 진행 방향의 뒤쪽으로 넘어가는 순간, 또는
  - 플레이어 반대쪽으로 달리며 700px 넘게 멀어진 경우 (크게 빗나가 화면 밖으로 날아가는 것 방지).
- 지나치면 0.45초 동안 진행 방향 그대로 미끄러지며 감속하고, **0.8초 휴식**한다.
  휴식이 끝나면 플레이어 쪽으로 돌아서 1단계(60 px/s)부터 가속을 다시 쌓는다.
- 500 px/s 미만에서는 플레이어를 지나쳐도 감속하지 않고 계속 가속한다.
- 플레이어는 빨라진 ANTARES를 옆으로 흘려보내 지나치게 만들고, 감속·휴식하는 등 뒤를 친다.

#### 들이받기: 넉백과 기절

- 속도와 상관없이 플레이어와 닿으면 들이받는다. 판정 거리는 프레임 가장자리 + 플레이어 몸체로,
  두 몸체가 겹치기 전에 판정한다.
- **넉백**: 플레이어를 ANTARES → 플레이어 방향으로 속도에 비례해 밀어낸다
  (속도 × 0.55: 60 px/s에서 약 33px, 700 px/s에서 약 385px). 약 0.25초에 걸쳐 감속하며 밀리고,
  아레나 경계에서 멈춘다. 플레이어 대시 무적 중에는 밀리지 않는다.
- **피해**: 속도에 비례해 최대 12 (700 px/s 기준).
- **기절**: 들이받은 ANTARES는 그 자리에서 0.6초 멈춘다. 이후 1단계부터 다시 추적한다.

#### 상태 연출

- 가속 중: 속도가 오를수록 분절 조각들이 진행 반대 방향으로 최대 4px 밀리고,
  빠른 회전과 잔상이 겹쳐 프레임이 흐려 보인다.
- 잔상: 0.04초 간격으로 기록한 과거 위치에 같은 오각 프레임을 낮은 알파로 다시 그린다.
  개수는 속도에 비례해 0~6개이고, 빠를수록 간격이 벌어져 꼬리가 길어진다. 새 파티클을 쓰지 않는다.
  색수차(빨강/청록 1~2px 어긋남)는 4단계 잔상에만 적용한다.
- 4단계: 코어가 경고색으로 바뀐다.
- 지나친 뒤 감속: 잔상이 감속에 맞춰 하나씩 사라지고, 코어가 점점 어두워진다.
- 휴식: 어두워진 코어가 휴식 시간 동안 원래 밝기로 돌아온다. 회전은 가장 느리다.
- 기절: 분절 프레임이 최대 3.5px로 떨리다 잦아들고, 코어가 깜박인다. 코어 위치는 흔들지 않는다.
- 코어는 어떤 단계에서도 흐리게 그리지 않는다. 흐려지는 것은 잔상과 분절 프레임뿐이다.

#### 수치

- 기본 체력 600. 접촉 피해는 통일된 몹 피해(초당 5)를 따르고, 들이받기는 별도로
  속도에 비례해 최대 12 피해와 최대 약 385px 넉백을 준다.
- 기절 0.6초, 감속 0.45초, 휴식 0.8초.
- 보상: XP 8 / 점수 350 / 스타더스트 4.
- 필드 동시 존재 수 제한이 있다 (4장 스폰 가이드라인 참고).

**읽힘**: 큰 붉은 분절 오각 프레임 + 쫓아올수록 빨라지는 회전과 잔상 + 들이받아 튕겨내거나 지나쳐 멈춰 섬 = 투우형 추적.

금지 사항:
- 닫힌 오각형 외곽선이나 별 오각형 연결로 그리지 않는다.
- 코어에 잔상·색수차·흐림·떨림을 적용하지 않는다.
- 가속과 분리된 별도의 돌진·조준 동작을 추가하지 않는다.
- 지나친 뒤 감속과 휴식 없이 곧바로 방향을 되돌리지 않는다.
- 플레이어와 겹친 채로 머무르지 않는다. 닿으면 넉백과 기절로 떨어진다.
- 투사체나 오라 능력을 추가하지 않는다.

## 5. 구현 체크리스트

### 공통

- [ ] 모든 적이 중앙 코어 + 별 노드 + 연결선 그래프로 읽힌다.
- [ ] 닫힌 원형 외곽선, 행성 표면, 강착 링을 사용하지 않는다.
- [ ] 오라 보조선의 알파값이 코어보다 낮다.
- [ ] 오라 비활성 시 보조선이 즉시 사라진다.
- [ ] 모든 노드가 동일한 `NodeAnchor`를 참조한다.
- [ ] 크기 변화는 선형 보간으로 처리한다.

### 적별

- [ ] `REGULUS`: 외장 구조를 갖춘 코어 + 단일 분절 보호막 + 최대 8개 코어 링크
- [ ] `ALCOR`: 상·하로 분리된 4개의 열린 가속 스트림 + 순차 점등
- [ ] `MAGNETAR`: 같은 방향으로 꺾인 4가지 + 과부하 3단계
- [ ] `UMBRA`: 빈틈을 남긴 3갈고리 별자리 + 흡수 카운터 + 흡수량 비례 폭발
- [ ] `COLLAPSE`: 3개의 포식 가지 + 단계별 노드 수축 + 흡수 시 XP 지급 없음 + 4단계 이후 성장 정지
