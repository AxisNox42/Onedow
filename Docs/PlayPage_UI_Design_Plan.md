## 0. 핵심 방향 (한 줄 요약)

**PLAY 화면 하나에서 무기 선택, 시련 ON/OFF, 출격까지 끝낸다. 중앙에는 선택 무기의 큰 히어로 별자리와 무기명·설명·6축 수치를 하나로 묶고, 중앙 하단에는 PLAY, 우측에는 시련 목록을 둔다. 시각적 우선순위는 중앙 무기 히어로 > PLAY > 시련 설정 > 보조 정보다. 실제 무기 선택은 다른 탭과 같은 좌측 하단 세로 라우트 레일에서만 수행한다.**

---

## 1. 구조 결정: 좌측 하단 라우트 레일 + 중앙 히어로 + 우측 시련 목록

### 왜 좌측 하단 라우트 레일인가

- 좌측 하단 세로 레일: 다른 탭의 `DISPLAY / AUDIO / SYSTEM / BACK` 라우트와 같은 시각 문법을 공유한다.
- 무기 선택을 한 곳에만 두어 중앙 성도와 하단 조작부가 서로 다른 선택 UI로 보이지 않게 한다.
- PLAY만 좌측 패널 전체를 차지하지 않으며, 중앙 히어로가 선택 상태와 무기 정보를 함께 보여 준다.

### 좌측 하단 라우트 레일 = "컨텍스트 바" (선택지를 바로 담는다)

무기가 2종(RIFLE / FIELD)뿐이라 모드 전환 없이 **세로 레일에 선택지를 직접 배치**한다:

```
WEAPONS
✦ RIFLE
✧ FIELD
◀ BACK
```

- 좌측 하단 `RIFLE / FIELD` — 유일한 무기 선택 입력. 선택된 값에 따라 중앙 히어로 별자리의 외형·색과 무기 정보가 바뀐다.
- 시련 선택은 우측 목록에서 각 항목을 `ON / OFF`로 직접 전환한다. PLAY 안에 시련 설정을 남겨 페이지 이동을 없앤다.
- 하단 `BACK` — 메인메뉴 복귀. 중앙 하단 `PLAY` — 현재 무기와 시련 설정으로 출격하는 주 액션.

### 3분할 역할

| 영역 | 역할 |
|---|---|
| **중앙 — 무기 히어로 별자리** | 시련 탭의 RIFLE/FIELD 별자리 외형을 크게 보여 주고, 이름·설명·6축 스탯을 같은 시각 블록에 결합한다. 무기 선택 입력은 하단 라우트에만 둔다. |
| **중앙 하단 — PLAY** | 현재 선택 상태로 출격하는 단일 주 액션. `bg_linear.png` 국소 광원을 낮게 깔아 클릭 지점을 잡아 준다. |
| **우측 — 시련 목록** | 6개 시련을 모두 나열하고 각 항목을 독립적인 ON/OFF로 전환한다. 활성 개수는 상단에 표시한다. |
| **좌측 하단 — 라우트 레일** | 다른 탭과 같은 세로 조작 구조. WEAPONS 그룹 아래 RIFLE/FIELD와 BACK만 둔다. |

## 2. 디자인 원칙: "무채움(無面) 3원칙"

1. **면 대신 선** — 구역 구분은 사각 패널/딤 없이 얇은 가이드 라인과 별자리 연결선으로만. 코너 브라켓 같은 프레임 장식도 쓰지 않는다.
2. **면 대신 점** — 선택 요소는 버튼 박스 대신 별 노드의 점등 상태(흐림 → 호버 → 점등+연결)로 표현.
3. **면 대신 문자** — 계층·구분은 문자 크기/자간/명도/정렬로. 구분선은 필요한 최소한만.

즉 화면 전체에 렌더되는 건 오직: **문자, 1px 선, 점(별), 텍스처 대비 필드, 그리고 플레이어의 바탕화면** 뿐이다.

---

## 3. 컨셉: "STAR CHART 위에서 그려지는 런 별자리"

- 이 게임은 **데스크탑 위 투명 오버레이**에서 돌아간다. PLAY 화면은 배경을 덮는 설정창이 아니라, **플레이어 화면 위에 떠 있는 밤하늘 성도(星圖)**.
- 메인메뉴와 시각적 연속: 메인메뉴의 별하늘 "다른 구역"을 확대해 들어온 느낌.
- 무기 프로필과 시련 ON/OFF 상태가 별을 찍어 하나의 런 별자리를 완성하는 의식. 완성된 별자리는 해당 런의 상징.

## 4. 화면 구성: 면 없이 층을 만드는 법

면(차폐/딤)을 쓰지 않으므로, 층위(depth)와 구역(zone)은 아래 수단으로만 표현한다.

| 목적 | 면 없이 쓰는 수단 |
|---|---|
| 구역 경계 | 코너 브라켓·테두리 없음. 공간 여백 + 문자 정렬 + 텍스처 대비 필드로 구역을 구분 |
| 시각적 층위 | 명도·선 굵기·점 크기 단계화 (배경 별 < 장식 선 < 정보 선 < 선택 노드) |
| 텍스트 가독성 | **1px 다크 아웃라인 + 소프트 섀도** (메인메뉴 텍스트 섀도 패스 재사용), 명도 ≥ 0.8 |
| 노드 강조 | 코어 점 `alpha ≥ 0.9` (사실상 불투명 점), 선택 시 제한적 글로우 — 글로우는 "점의 발광"이지 면이 아니므로 허용 |
| 연결선 | 1px + 느린 파동 알파 (`0.5 ~ 0.7`), 완성 순간 한 번 밝아졌다 안정 |

배경 처리:

- **전체 화면 딤/밴드/차폐 "면" 금지.** 바탕화면과 별 파티클이 그대로 비친다.
- 대신 **기존 그라디언트 텍스처를 이용한 국소 대비 필드**를 사용한다 — 딱딱한 사각 면이 아니라 부드럽게 흐려지는 텍스처 기반이므로 무채움 원칙과 충돌하지 않는다.
  - `bg_linear.png` 계열 (`DrawPersistentSceneLeftVignette`/`DrawSceneLeftVignette`, `Scenes.cpp:258-270`) — PLAY에서는 **좌측 하단 세로 라우트와 중앙 하단 PLAY 뒤의 국소 대비 광원**으로만 사용한다. 별자리 뒤에는 원형 `CircleTexture.png`만 둔다. 다른 페이지는 좌측 레일 그대로.
  - `CircleTexture.png` 계열 — 우측 정보 패널의 텍스트 블록 뒤, 성도의 선택 노드 뒤 작은 원형 대비 필드 (메인메뉴의 bounded radial contrast field와 같은 기법).
  - `LeftGradient.png` / `LineTexture.png` — 구역 경계의 얇은 선·그라디언트 표현에 활용. 카드 박스 대체 재료.
  - `PanelTexture.png` — 면 없이 갈 때는 사용하지 않되, 극단적 배경 fallback(§5) 시에만 제한적으로 검토.
- 유일하게 허용되는 발광은 **선택된 별 노드, 무기 프로필의 원형 광원, PLAY의 로컬 글로우** (반경 작게, 각 콘텐츠 주변만).
- 스캔라인/CRT 효과는 메인메뉴와 동일 정책 (CRT ON 시 메뉴 자체 스캔라인 스킵 — MM-11 결정 계승).

텍스처 사용 규칙:

- 텍스처 대비 필드는 **"문자를 읽게 하는 도구"**이지 장식이 아니다. 정보가 없는 빈 공간에는 깔지 않는다.
- 알파는 낮게 (하단 레일 `0.15 ~ 0.30`, 노드/텍스트 뒤 원형 필드 `0.2 ~ 0.35` 시작값) — 스크린샷 3종으로 확정 (§5).
- 페이지 전환 시 깜빡임/노출 방지를 위해 대비 필드는 콘텐츠 reveal 게이트 밖에서 그린다 (기존 `bg_linear.png` 주석 정책, `Scenes.cpp:265-267` 계승).

## 5. 가시성 규칙 (무채움 전제)

면 없이 읽히게 만드는 장치들:

1. **문자에 아웃라인·섀도 의무화** — 모든 라벨/수치에 1px 다크 아웃라인. 이게 유일한 "보조 레이어"이며, 이조차 사각 면이 아니라 글리프 주변만 처리.
2. **노드 코어 불투명화** — 별의 중심 점은 `alpha ≥ 0.9`로 찍어 어떤 바탕 위에서도 점 자체는 항상 보이게.
3. **상태 기반 알파 3단계** (메인메뉴 결정 계승): Idle 흐림 → 호버 미세 점등 → 선택 점등+연결. 별자리 선은 "텍스트보다 낮은 시각 우선순위, 그러나 Idle에서도 구조 추적 가능" 수준.
4. **선택 시에만 글로우** — 글로우 범위는 노드에서 연결선 방향으로만 살짝. 전체 화면 블룸 금지 (`UI_RunConfig_Unification_Plan.md` 준수).
5. **텍스처 대비 필드** (§4) — `bg_linear.png` 좌측 하단 라우트/중앙 하단 PLAY 국소 광원 + `CircleTexture.png` 무기 프로필과 국소 필드. 문자 아웃라인과 병용: 아웃라인이 점 수준의 보장, 텍스처 필드가 구역 수준의 보장.

### 밝은/움직이는 바탕 대응 (fallback 단계)

면 없이 가는 만큼 극단적 배경에서의 fallback을 단계적으로 정의:

1. (기본) 문자 아웃라인 + 노드 코어 불투명 + 텍스처 대비 필드 기본 알파.
2. 가독성 붕괴 시 → **문자 아웃라인을 2px/더 진하게** + 하단 레일/국소 필드 알파 상승 (`0.3 → 0.45` 범위).
3. 그래도 안 될 시 → 선택 노드 글로우 반경 확대, `CircleTexture.png` 필드 반경 확대.
4. **전역 딤 면 도입은 최후의 수단**으로만 검토 — 도입하더라도 `PanelTexture.png`/radial 그라디언트 같은 부드러운 텍스처 기반 국소 필드로 한정. 가능하면 1~3단계로 커버하는 것이 목표.

검증 시나리오 (반드시): **어두운 바탕 / 밝은 바탕 / 움직이는(동영상) 바탕** 3종 × 상태(Idle/호버/선택/완성) 조합 런타임 스크린샷.

## 6. 레이아웃 (1640×910 기준, `uiS` 비례)

```
  PLAY // RUN PREPARATION                                      [ESC]
        ↑ 헤더는 문자+정렬만. 테두리·브라켓·구분선 없음                    │
                                                                         │
                  중앙 히어로 별자리                         우측 시련 ON/OFF
                 (CircleTexture 광원)                         TRIALS  3 / 6 ACTIVE
                     RIFLE                                  ● S1       ON
             PRECISION / SINGLE TARGET                       ● S2      OFF
                                                            ● S3       ON
                 ┌──────────────┐                           ...
                 │ WEAPON SYSTEM│                            ● S6      OFF
                 └──────────────┘
                 DAMAGE ─━━ 50
                 FIRE RATE ━━━ 5.0/s
                 RANGE ─━━ 900

                     READY / 3 TRIALS ACTIVE
                         PLAY / START RUN

  WEAPONS
  ✦ RIFLE
  ✧ FIELD
  ◀ BACK
     ↑ 좌측 하단 세로 라우트 / 중앙 하단 PLAY / bg_linear 국소 광원
```

- **중앙 무기 히어로 별자리** — 시련 탭의 `DrawWeaponPowerConstellation()`을 재사용해 선택된 무기 하나의 RIFLE/FIELD 외형을 크게 그린다. `CircleTexture.png`를 어두운 대비층 + 넓은 색상 광원층 + 안쪽 무기 색상 틴트층으로 별자리 뒤에 배치한다. 무기명·설명·6축 스탯은 이 히어로 영역에 붙이고, 별자리 자체는 클릭하지 않는다.
- **중앙 하단 무기 수치 스트립** — 6개 값을 3열 2행으로 배치해 별자리 아래에 연결한다. 별도 카드/패널을 만들지 않고 얇은 바와 값의 대비만 사용한다.
- **우측 시련 목록** — 6개 항목을 항상 노출하고 `ON / OFF`를 직접 클릭한다. 목록이 시련의 유일한 입력 표면이므로 별도의 TRIALS 탭/중앙 궤도 선택 UI를 두지 않는다.
- **좌측 하단 라우트 레일** — `WEAPONS` 그룹 아래 `RIFLE` / `FIELD`와 `BACK`만 둔다. 버튼은 라인+문자+작은 별 노드 아이콘이며 `bg_linear.png` 국소 레일이 뒤를 받친다.
- 헤더 우측에는 `[ESC]` 힌트만 (BACK이 하단에 있으므로 중복 배치 금지). ESC/우클릭 뒤로가기 단축키 유지.

## 7. 상호작용 흐름

1. 메인메뉴 PLAY → STAR CHART 펼침 (기존 `s_MainMenuRunConfigPanel` / `playExit` 진출입 구조 유지).
2. 좌측 하단 `✦ RIFLE` / `✧ FIELD` 클릭 → 중앙 무기 히어로 별자리의 외형과 색 변경 + 무기 설명/6축 스탯 갱신.
3. 우측 시련 목록의 각 행 클릭 → 해당 시련을 `ON / OFF` 전환하고 상단 활성 개수를 갱신한다.
4. 중앙 하단 `PLAY` → collapse + 별자리 점등 연출 → 현재 무기와 시련 설정을 유지한 채 `FinalizeLoadout` → READY.
5. 하단 `◀ BACK` 또는 ESC/우클릭으로 메인메뉴 복귀.

## 8. 구현 작업 목록 (우선순위)

1. `Scene_RunConfigInline` 재배치: 중앙 무기 히어로 별자리·준비 정보 + 우측 시련 ON/OFF 목록 + 중앙 하단 PLAY, `canvasPage` 토글 제거.
2. **무채움 렌더 규칙 적용** — 기존 패널/카드 박스 fill 전부 제거 → 여백 + 문자 정렬 + 얇은 가이드 라인으로 대체. 코너 브라켓 등 프레임 장식도 사용하지 않음. (§4)
3. **문자 아웃라인/섀도 패스 + 노드 코어 불투명화** 적용 (§5-1, 5-2). 상수 분리: 아웃라인 두께/색, 코어 알파, 글로우 반경.
4. **텍스처 대비 필드 배치** — `bg_linear.png`는 하단 레일/중앙 PLAY에만 배치하고, 무기 프로필에는 `CircleTexture.png` 원형 광원만 사용한다. 페이지 reveal 게이트 밖 렌더링 유지. 상수 분리: 레일 알파, 원형 프로필 필드 알파/반경.
5. **하단 라우트 레일 구현** — BACK / WEAPONS 그룹(RIFLE·FIELD 선택) / 중앙 하단 PLAY 버튼, 그룹 구분과 선택 상태 시각화(점등). 라벨은 기존 다국어 시스템.
6. 상태 기반 알파 3단계 (§5-3) — Idle/호버/선택.
7. 시련 목록 직접 토글 구현 (각 항목 ON/OFF, 활성 개수 실시간 갱신).
8. 레거시 `Scene_RunConfig` (`Scenes.cpp:6042-6986`) 및 난이도 잔재 제거 (호출 경로 grep 후).

## 9. 리스크 / 주의

- **최대 리스크 = 가독성.** 면 없이 가는 만큼, 어두운 바탕에서는 글자가 번지고 밝은 바탕에서는 흐려질 수 있음. §5 fallback 단계(문자 아웃라인 → 텍스처 필드 알파 상승 → 글로우 확대 → 국소 radial)를 코드 상수로 미리 분리필 것.
- 텍스처 필드도 과용하면 "면"과 다를 바 없어짐 — 정보가 있는 위치(하단 바, 우측 패널, 선택 노드)에만 배치하고, 빈 공간 깔지 않기.
