# Astral Enemy Blueprints v6.0

## 0. 이번 개편의 기준

인게임 적을 아웃게임의 별자리 UI와 연결되는 기하학적 신호체로 리디자인한다.

이번 버전에서 가장 중요한 것은 장식을 늘리는 것이 아니라, 적마다 **한눈에 구분되는 하나의 실루엣**을 주는 것이다.

- `ROTOR`: 사각형 프레임 1개
- `DDOS`: `ROTOR`보다 작은 삼각형
- `RangedMob`: 중앙 코어를 가진 원형 관측기
- `GRAVIS`: 중력장으로 영역을 잡는 3T 정예몹
- `SPAWNER`: 이름과 외형을 별도 확정하기 전까지 보류

게임플레이 역할과 내부 ID는 유지한다. 표시 이름만 변경할 수 있도록 별도 데이터로 관리한다.


| 내부 ID       | 현재 역할      | 표시 이름          |
| ----------- | ---------- | -------------- |
| `NORMAL`    | 기본 추적형     | `ROTOR`        |
| `DDOS`      | 다수 신호 압박형  | `SWARM` (가칭)   |
| `RangedMob` | 거리 유지 원거리형 | `SCOPE` (가칭)   |
| `GRAVIS`    | 중력장 정예형    | `GRAVIS`       |
| `SPAWNER`   | 적 생성 지원형   | `GENESIS` (가칭) |


이름은 구현 전에 최종 확정하며, 이름 변경이 ID나 저장 데이터에 영향을 주어서는 안 된다.

## 1. 공통 외형 규칙

### 1.1 공통 구성

모든 적은 아래 순서를 기본으로 한다.

1. **Core**: 중앙의 밝은 핵심 코어
2. **Nodes**: `CircleTexture`로 그리는 별 또는 표시점
3. **Edges / Frame**: 노드나 코어를 보조하는 얇은 선
4. **Silhouette**: 적별로 하나만 선택하는 외곽 구조

적의 종류를 알아보기 위해 여러 프레임을 겹치지 않는다. 실루엣은 최대 1개, 보조 링이나 보조선도 필요한 만큼만 사용한다.

### 1.2 크기 우선순위

- 중앙 코어가 모든 별과 표시점보다 크고 밝아야 한다.
- 별은 크게 보여도 되지만 코어의 밝은 중심보다 작아야 한다.
- 코어 기준 크기를 `1.0`으로 할 때 일반 노드는 `0.40 ~ 0.70`, 강조 노드는 최대 `0.78`로 제한한다.
- 노드 후광이 커 보여도 `CircleTexture`의 실제 중심점은 코어를 덮지 않는다.
- 연결선은 별보다 얇아야 하며, 별의 후광보다 어둡게 처리한다.

### 1.3 좌표와 텍스처 일치

노드 위치를 선과 텍스처에서 각각 계산하지 않는다.

```text
NodeAnchor {
    position
    radius
    brightness
}
```

적별 `NodeAnchor[]` 하나를 만들고 다음 렌더링에 공동 사용한다.

- 연결선의 양 끝점
- `CircleTexture`의 중심
- 노드 중심의 밝은 점
- 공격 준비와 이동 시 노드 보간 위치

텍스처 렌더링 시 별도의 임의 `x/y` 보정값을 넣지 않는다. 텍스처 쿼드는 항상 `anchor.position`을 중심으로 정렬한다.

### 1.4 렌더 순서

1. 얇고 낮은 알파의 연결선 또는 프레임
2. 코어와 노드의 `CircleTexture` 후광
3. 노드 중심점
4. 중앙 코어

원형 그림자를 버텍스 원이나 불투명한 면으로 대체하지 않는다. `CircleTexture`가 로드되지 않을 때만 단순 폴백을 사용한다.

## 2. 적별 디자인

### 2.1 `NORMAL` - ROTOR

**사각형 프레임 하나만 사용하는 기본 적.**

- 중앙에 코어 1개를 둔다.
- 코어를 감싸는 얇은 사각형 프레임 1개만 사용한다.
- 사각형의 네 꼭짓점 또는 필요한 꼭짓점에 `CircleTexture` 노드를 최대 4개 배치한다.
- 프레임과 노드는 느리게 회전한다. 두 번째 프레임, 삼각형 중첩, 별도 궤도는 추가하지 않는다.
- 이동 방향은 사각형 전체의 미세한 기울기와 코어의 지연으로만 표현한다.

**읽힘:** 단일 사각 프레임 + 중앙 코어 = 가장 기본적인 추적형 적.

### 2.2 `DDOS` - SWARM (가칭)

**ROTOR보다 작고 가벼운 삼각 신호.**

- 중앙 코어 1개와 작은 삼각형 프레임 1개를 사용한다.
- 전체 크기는 `ROTOR`의 약 `0.65 ~ 0.80`으로 설정한다.
- 삼각형 꼭짓점에 `CircleTexture` 노드 3개를 배치한다.
- 선은 짧고 얇게 하며, 코어 주변에 작은 흔들림을 준다.
- 여러 마리가 모였을 때 서로 연결된 것처럼 보이지 않도록 개체 간 연결선은 그리지 않는다.
- 증식 또는 압박 상태에서는 세 노드가 순차 점등된다.

**읽힘:** 작은 삼각형 + 빠른 신호 점멸 = 다수 압박형 적.

### 2.3 `RangedMob` - SCOPE (가칭)

**중앙 코어를 가진 원형 관측기.** 제공된 원형 HUD 이미지의 요소를 참고하되, 화면 장식이 아니라 적의 실루엣으로 단순화한다.

- 중앙에 `CircleTexture` 기반 코어를 둔다.
- 코어 주변에 얇은 원형 링 2개를 둔다. 링은 닫힌 면이 아니라 선 또는 짧은 호 조각으로 그린다.
- 가장 바깥쪽에는 희미한 점선 궤도를 1개만 사용한다.
- 위, 아래, 좌, 우에 작은 관측 마커를 최대 4개 배치하고 `CircleTexture`로 표현한다.
- 마커와 코어를 잇는 선은 필요할 때만 사용하며, 선은 마커보다 얇게 유지한다.
- 원형 링과 마커는 공격 방향에 맞춰 아주 느리게 회전하고, 중앙 코어는 방향과 무관하게 고정한다.
- 공격 준비 중 공격 방향의 마커만 밝아지고, 링의 일부가 해당 방향으로 정렬된다.
- 발사 순간 링이 짧게 수축하고 코어가 한 번 펄스한다.

**읽힘:** 중앙 코어 + 원형 관측 링 + 한쪽 마커 점등 = 원거리 조준형 적.

금지 사항:

- 화면 전체를 덮는 거대한 HUD를 만들지 않는다.
- 링을 여러 겹 추가해 보스처럼 보이게 만들지 않는다.
- 코어보다 큰 마커 후광을 사용하지 않는다.

### 2.4 `SPAWNER` - GENESIS (가칭, 외형 보류)

현재는 이름과 역할만 임시로 둔다. 다른 적의 실루엣을 재활용해 급하게 확정하지 않는다.

확정 전 검토할 방향은 아래 두 가지다.

- **핵 중심형:** 큰 코어와 짧은 생성 슬롯을 두고, 생성 시 슬롯이 열린다.
- **군집 중심형:** 코어 주변에 작은 노드가 모였다가 생성 순간 바깥으로 퍼진다.

추천 방향은 **핵 중심형**이다. `ROTOR`의 사각형이나 `SWARM`의 삼각형을 복사하지 않고, 큰 중앙 코어와 3개의 생성 포트만으로 지원형 역할을 보여줄 수 있다.

단, 생성 포트의 모양과 노드 수는 실제 생성 연출을 확인한 뒤 별도 버전에서 확정한다.

### 2.5 `GRAVIS` - GRAVIS

**3T 정예몹. 중력장으로 공간을 장악하는 행성형 적.**

- 중앙 코어를 크게 두고, 그 바깥에 고정 반경의 중력장 영역을 둔다.
- 코어 주위에 얇은 링 또는 불완전한 궤도 1개만 사용한다. 여러 겹의 보스형 링은 넣지 않는다.
- 영역 안으로 들어온 플레이어는 중심으로 천천히 당겨진다.
- 이 몹의 탄환은 직선 성질을 유지하되, 중력장 안에서만 앞으로 진행하면서 휘거나 공전하는 궤적으로 보이게 한다.
- 이동은 공격형 추적이 아니라 느린 구역 장악형으로 둔다.
- 하위 몹의 탄환 편향 규칙을 완성형으로 보여주는 상위 계층으로 사용한다.

**읽힘:** 큰 코어 + 중력장 반경 + 굽는 탄환 = 공간을 조작하는 정예몹.

금지 사항:

- 중력장을 화면 전체로 확장하지 않는다.
- 탄환이 역방향으로 튀거나 정지한 뒤 순간이동하듯 보이게 만들지 않는다.
- 기존 `SCOPE`의 원형 관측기 실루엣을 그대로 복사하지 않는다.
- 보스급 HP 바나 전용 대형 연출은 붙이지 않는다.

## 3. 상태 표현

새 파티클 시스템을 추가하지 않고 기존 코어, 노드, 프레임의 위치와 알파를 이용한다.


| 상태    | 표현                                |
| ----- | --------------------------------- |
| 대기    | 프레임 또는 링이 느리게 회전하고 코어는 안정적으로 유지   |
| 이동    | 외곽 구조가 진행 방향을 조금 늦게 따라감           |
| 공격 준비 | 관련 노드와 링 일부가 코어 쪽으로 정렬되고 밝아짐      |
| 공격    | 프레임이나 링이 짧게 수축한 뒤 복귀              |
| 피격    | 중앙 코어만 짧게 강하게 밝아짐                 |
| 사망    | 연결선이 먼저 끊기고 노드가 바깥으로 흩어진 뒤 코어가 꺼짐 |

## 4. 구현 체크리스트

### 공통

- [ ] 중앙 코어가 모든 별보다 크고 밝다.
- [ ] 모든 별과 마커가 `CircleTexture`의 중심과 정확히 일치한다.
- [ ] 연결선은 별보다 얇고 어둡다.
- [ ] 선, 텍스처, 중심점이 동일한 `NodeAnchor`를 참조한다.
- [ ] 텍스처 로드 실패 시에만 폴백 원형을 사용한다.
- [ ] 개발 실행 파일과 배포 실행 파일의 `Resource` 경로에 텍스처가 포함된다.

### 적별

- [ ] `ROTOR`: 사각형 프레임 1개만 사용
- [ ] `SWARM`: `ROTOR`보다 작은 삼각형 1개
- [ ] `SCOPE`: 코어 + 얇은 원형 링 + 최대 4개 관측 마커
- [ ] `GRAVIS`: 큰 코어 + 1개의 중력장 영역 + 직선 편향 탄환
- [ ] `GENESIS`: 디자인 확정 전까지 기존 외형 복사 금지

### 금지 사항

- [ ] `ROTOR`에 삼각형이나 두 번째 프레임을 추가하지 않는다.
- [ ] `SWARM`을 `ROTOR`보다 크게 만들지 않는다.
- [ ] `SCOPE`의 링과 마커를 코어보다 크게 만들지 않는다.
- [ ] `GRAVIS`를 보스급 구조로 키우거나 화면 전체 중력장으로 바꾸지 않는다.
- [ ] 연결선이 별보다 굵게 보이지 않는다.
- [ ] 외형 작업과 함께 체력, 방어력, 스폰률, 공격 패턴을 임의로 변경하지 않는다.

최종 기준은 다음과 같다.

> **ROTOR는 사각형 하나, SWARM은 작은 삼각형 하나, SCOPE는 중앙 코어를 가진 원형 관측기 하나로 즉시 구분되는가?**
