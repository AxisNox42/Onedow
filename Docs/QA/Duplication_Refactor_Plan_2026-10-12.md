## 1. 목표와 확정 사항

같은 게임 규칙을 여러 곳에서 따로 구현하거나, 같은 수치를 사람이 여러 곳에 맞추는 구조를 없앤다. 먼저 전체 후보와 의존 관계를 조사하고, 책임을 정한 뒤 작은 단위로 통합한다. 파일 분리 자체를 완료 기준으로 삼지 않는다.

| 항목 | 합의 |
|---|---|
| 작업 순서 | 전체 중복 목록·의존 관계 조사 → 통합 구조 설계 → 작은 단위 구현 |
| 기존 버그 | 이번 작업 범위에서 처리하되 구조 변경과 별도 ID/diff/검증으로 먼저 수정. 관련 없는 버그는 별도 기록 |
| 의도 불명인 차이 | 항목별로 결정. 코드 한 경로를 임의로 정답으로 삼지 않음 |
| 콘텐츠·밸런스 개발 | 리팩터링 기간에도 계속 진행 |
| 재발 방지 | **통합 완료 영역은 신규 콘텐츠도 반드시 공통 경로를 사용** |
| 일반 스웜 흡혈 | **모든 처치 수단에서 기본 처치당 흡혈의 100%**. 기존 탄환 경로의 ×0.2도 변경 |
| 투척 스웜 보상 | 모든 처치 수단에서 점수·XP·스타더스트·흡혈 보상 없음 |
| 투척 스웜 집계 | **모든 처치 수단에서 콤보·도감만 증가**. 런 킬·전쟁군주·흡혈마 누적 제외 |

일반 스웜의 처치당 흡혈과 흡혈마의 N킬마다 회복은 별도 규칙이다. 일반 스웜의 N킬 누적은 현재 규칙을 유지하고, 투척 스웜은 누적 대상에서 제외한다.

## 3. 중복 판정과 완료 기준

중복은 네 종류로 분류한다.

1. **규칙 중복:** 처치 보상·획득 자격·시련 효과처럼 같은 판단을 여러 곳이 독립적으로 수행한다.
2. **데이터 중복:** 효과 수치·설명 숫자·도감·표를 별도로 수정해야 한다.
3. **상태 목록 중복:** 초기화·복원·저장·취소 시 같은 필드를 사람이 나열한다.
4. **기계적인 구현 중복:** 클램프·알파 보정·화면 밖 판정처럼 입력과 출력 계약이 같은 계산이 반복된다.

용도가 다른 정책은 차이를 명시해 보존한다. 예를 들어 충돌 우선순위와 도감 해금 티어, 스코프 연사와 짐벌 단발은 값이나 상태 전이를 무조건 같게 만들지 않는다. 장면의 `SceneCtx` 지역 별칭이나 종류별 고유 연출은 문법이 닮았다는 이유만으로 통합하지 않는다.

각 후보는 다음 조건을 충족해야 완료다.

- 권위 있는 함수·정의·상태 소유자가 한 곳으로 정해져 있다.
- 기존 사용처가 모두 공통 경로로 이관되어, 호출부에 같은 보상식·선택 자격식·표시 수치가 남지 않는다.
- 의도된 차이는 그 소유자 안의 명명된 정책이나 정의로 표현하고, 이유와 검증 사례를 남긴다.
- 불명확한 규칙을 임의로 바꾸지 않는다. 결정이 필요한 부분만 미결로 남기고 독립적인 통합은 진행한다.
- 해당 동작의 회귀 검증을 통과하고, 더 이상 호출되지 않는 구형 경로를 제거한다.
- 같은 변경이 다시 여러 파일의 수동 동기화를 요구하지 않는지 확인한다.

단순 중복 검출률 0%가 완료 기준은 아니다. **같은 규칙·같은 사실을 독립적으로 관리하는 곳이 없는 상태**를 목표로 하며, 남기는 반복은 이유를 기록한다.

## 5. 통합 구조와 의존 방향

### 책임 단위

- **전투/보상:** 보상 정의, 보상 자격, 집계/회복 적용이 규칙을 소유한다. 탄환·레이저·차크람 등은 피해를 주고 기존 시점에서 공통 보상 함수를 호출한다.
- **콘텐츠 정의:** 몹·무기·증강·시련 각각의 정의가 그 수치의 출처다. 시뮬레이션과 UI/도감은 같은 정의를 읽는다. 무관한 모든 숫자를 거대한 `Balance.h` 한 파일에 넣지 않는다.
- **런 상태:** 지속 카운터, 파생 스탯, 증강 부속 런타임, 새 런 전용 상태의 수명을 구분한다. 재계산·대혼란·새 런은 공통 원시 동작에 서로 다른 명명된 정책을 적용한다.
- **UI:** 기존 언어 선택·레이아웃·입력 계층을 확장한다. 화면은 데이터·선택 정책을 소유하고, 공통 rect/텍스트/키 반복 계산을 사용한다.
- **설정:** 항목 메타데이터와 snapshot/diff/apply가 같은 항목 정의를 사용한다. 효과 적용은 각 시스템의 소유 경계를 유지한다.

의존 방향은 다음과 같다.

```text
main / 장면 / 충돌 / 무기별 실행부
    ├─ 공통 보상·시련·스탯 재계산 규칙 ── 도메인별 정의·런 상태
    └─ UI 표시/입력 ── 공통 UI 도구 및 읽기용 콘텐츠 정의

코덱스 기록·스타더스트 생성·연출은 보상 적용 경계에서 연결
순수 수치/자격 계산은 창·OpenGL·도감 화면·거대한 GameContext에 의존하지 않음
```

현재 `CollisionSystem.h`는 `Juice.h`와 `Codex.h`까지 직접 포함한다. 규칙을 옮기기만 하고 새 헤더가 기존 전역과 렌더 의존을 모두 포함하면 구조 개선이 아니다. 계산에 필요한 작은 입력을 전달하고, 기록·드롭·연출은 적용 경계에서 연결한다. 별도 이벤트 버스, ECS 전환, 범용 플러그인 구조는 이번 계획의 선행 조건이 아니다.

### 처치 보상의 구체적인 설계 계약

`GrantKillReward`는 가칭이다. 실제 자료형·파일 수는 0단계 설계에서 최소로 정한다.

1. 일반 몹/스코프를 보상 대상 정보로 변환하는 얇은 두 진입점을 허용한다. 점수·회복·킬 집계 본문은 하나만 둔다.
2. 입력은 대상 종류·투척 여부·보상 처리 상태·필요한 런 스탯/모드다. 처치 수단은 확정된 수단별 효과나 진단이 필요할 때만 포함하고, 동일 보상 규칙을 다시 수단별로 분기하지 않는다.
3. XP·스타더스트·점수·콤보·도감·런 킬·흡혈 누적 자격은 서로 구분한다. 단일 `rewardMult`를 모든 값에 곱하지 않는다. 스웜 흡혈은 100%, 현재 점수 배율 ×0.2는 별도 유지다.
4. 이미 보상 처리한 대상은 효과가 없어야 한다. **무보상 대상도 처리 완료로 표시**해 공통 사망 루프가 다시 지급하지 않도록 한다. 보상 처리와 사망 연출 완료는 구분한다.
5. 투척 스웜은 콤보·도감만 증가한다. 런 킬·전쟁군주 스택·처치당 흡혈·흡혈마 누적·모든 자원 지급은 하지 않는다.
6. 레이저의 레거시 필드 사용과 일반 몹의 흡혈 누락을 공통 적용 경로로 해결한다. 디버그 편집 UI의 레거시 필드 노출도 이관/제거한다.
7. 현재 `SpawnKillStardust`와 `ReleasePendingStardust`가 관리하는 제네시스·퀘이사 지연 드롭을 유지한다. XP를 처치 즉시 직접 더하는 방식으로 바꾸지 않는다.
8. 탄환·레이저의 즉시 보상 호출과 기타 사망 루프의 처리 시점은 유지한다. 새 중앙 큐 도입이나 고정 업데이트 순서 변경은 별도 작업으로 분리한다.
9. `SpawnDeathEffect`, 엘리트 히트스톱, 연쇄 폭발, 스코프 해킹 발사 등은 해당 수명/발동 조건을 유지한다. 반복되는 부분만 공유하고, 보상 호출 1회화 때문에 누락·중복되지 않도록 확인한다.
10. `RUNNING/DYING`, 창의적 모드에서의 회복 차이는 별도 규칙 결정/검증 대상이다. 구조 통합으로 조용히 통일하지 않는다.

## 6. 구현 전 의존 관계

```text
0. 전체 후보·호출 관계·규칙 소유자 설계
  └─ 1. 현재 동작 기준과 회귀 검증 최소 경로 확보
       ├─ 2. BEH 별도 수정 후 기준을 보존하며 처치 보상 5경로 통합
       ├─ 3. 콘텐츠 수치·런 상태·증강 자격 단일 출처화
       └─ 4. 구형 도감 진입 전환 → 공통 UI → 설정 정의/동작 통합
                └─ 5. 남은 기계적 중복·종류별 공통 부분 정리 + 전수 재검색
```

이것은 작업 의존 관계이며 별도 에이전트 병렬 구현 지시가 아니다. 2·3·4의 서로 독립적인 설계 검토는 먼저 진행할 수 있지만 같은 파일을 동시에 크게 바꾸지 않는다. 한 영역의 승인된 동작과 이관 경로가 확정되면 그 작은 단위를 구현한다.

## 8. 콘텐츠·밸런스 개발 병행 규칙

1. 파일 전체 장기 재작성보다 규칙 하나를 끝까지 이관하는 짧은 변경을 만든다. 구조 이관·버그/규칙 변경·밸런스 조정은 구분 가능한 커밋/변경으로 남긴다.
2. 작업 단위 시작/종료 때 해당 파일의 다른 변경을 확인한다. 현재 수정 중인 마그네타·퀘이사 등 코드를 오래된 엑셀 상태로 덮어쓰지 않는다.
3. **통합 완료 영역:** 신규 기능도 공통 정의/함수를 확장한다. 기존 파일에 보상식·초기화 목록을 복사하는 우회 경로는 허용하지 않는다.
4. **통합 전 영역:** 신규 기능의 수정 위치를 현행 체크리스트로 추적하고 중복 목록에 즉시 반영한다. 새로 만든 복사가 영구 구조가 되지 않도록 해당 통합 작업에 편입한다.
5. 구조 작업의 대상 경계를 콘텐츠 개발자에게 알리고, 같은 몹/증강 정의를 수정해야 하면 짧은 작업 단위의 순서를 조정한다. 전체 콘텐츠 동결을 전제로 하지 않는다.
6. `AGENTS.md`에는 조사/설계 이후 확정된 공통 진입점·숫자 출처·저장 ID 보존·검증 명령·새 규칙 금지 사항을 기록한다. 이번 계획안 작성만으로 프로젝트 지침 파일을 새로 만들지는 않았다.
7. 기존 로드맵 O/P/Q/R/S/U/V와 이 계획의 대응 관계를 유지한다. QA 증상 행은 남겨 추적하고 구조 티켓과 연결한다. 미검증 항목을 Clear로 바꾸지 않는다.

## 9. 검증 계획

### 보상 행렬

| 축 | 확인 사례 |
|---|---|
| 대상 | 일반 몹, 일반 스웜, 투척 스웜, 스코프, 제네시스, 퀘이사 |
| 수단 | 탄환, 레이저, 차크람/드론 등 공통 사망 경로, 전기장, 연쇄 폭발 |
| 보상/집계 | 점수, XP 드롭값, 스타더스트, 콤보, 도감, 런 킬, 전쟁군주 임계값, 처치당 흡혈, N킬 회복 |
| 경계 | 중복 호출, 같은 스텝에서 여러 수단의 사망 확인, HP 상한, N-1→N킬, 999→1000킬, 투척·일반 스웜 구분 |
| 시간·상태 | 지연 드롭 1회, 사망 연출 1회, 연쇄 폭발 순서, RUNNING/DYING, Creative 회복 정책 |

순수 계산·자격·상태 적용은 기존 assert 기반 C++ 테스트 방식으로 검증한다. 실제 탄환/레이저/공통 루프 연결도 확인해야 하며, 계산 함수만 통과한 것으로 이관 완료 처리하지 않는다. 시각/입력 동작은 기존 스모크와 수동 플레이를 사용한다.

### 나머지 영역

- 시련: 시작/임계 직전/임계/최대 구간, 미선택·복수 선택, UI 합계와 실제 배율.
- 몹/무기/증강: 기본값과 진행·메타·보유 증강 적용값 구분, 도감/설정표 숫자 의미, enum/예약 슬롯 호환.
- 런 상태: 일반 재계산, 증강 교체, 대혼란, 재시작 각각에서 카운터·스킬·장부 보존/초기화.
- 획득 자격: 중복 카탈로그 타입, once-only, retired, 선행조건, 디버프 추첨 및 특수 추첨 차이.
- 설정: 변경→저장→재실행, 변경→폐기, 즉시 적용값 복원, 기본값·범위 검증, 구 저장 파일 로드.
- UI/렌더: KR/EN/JP, 작은/큰 화면, rect와 hover 일치, Alt+Tab, 화면 재진입, darken/일반/회전 그리기 후 GL 상태.

기존 검증 자원: `scripts/build_windows.ps1`, `scripts/test_genesis_launcher.ps1`, `test_quasar_beam.ps1`, `test_quasar_nova.ps1`, `test_regulus_beam.ps1`, `test_magnetar_field.ps1`, `test_mob_death_fx.ps1`, `test_blur_windows.ps1`, `scripts/smoke_ui.ps1`. 새 `.cpp`를 추가하면 Visual Studio와 CMake 소스 목록을 모두 갱신한다. Windows 빌드를 기본 검증으로 하고 플랫폼 공통 변경에는 macOS 빌드도 확인한다. CI 확대는 로컬 검증 흐름이 안정된 다음 적용한다.

| D-05 | 무기 표가 보여줄 기준 | 추천: 무기 기본 성능과 전기장 펄스 성능을 의미에 맞게 표시하고 메타 적용 예상치는 별도 역할로 구분. 임의 밸런스 변경 없이 실제 정의 사용 | DL-11 구현 전 |

TD-01/02의 거대 함수는 규칙 통합 과정에서 필요한 책임부터 분리한다. TD-03의 몹 상태 전체 재설계, TD-09의 예약 슬롯 전면 생성화, TD-12의 게임/VFX RNG 분리, TD-13~15 성능 최적화, TD-21 릴리스 디버그 정책은 독립적인 후속 티켓으로 관리한다. 이 작업을 중복 제거의 선행 조건으로 묶지 않는다. 성능 개선은 프로파일 결과가 있을 때 결정한다.

TD-18/19/20의 지침·기준 문서·검증 경로는 이번 작업을 유지하기 위해 필요한 최소 범위부터 반영한다. 기존 QA 파일 이동/삭제나 저장 데이터 정리, 릴리스/배포는 이 계획안의 작성 범위에 포함하지 않는다.

## 11. 다음 작업 단위

2026-10-12에 **전체 파일의 정적 구조·중복·의존 관계 조사**를 완료했다. [전체 조사 보고서](D:/01_Study/02_OpenGL/Onedow/Docs/QA/CodeStructure_Audit_2026-10-12/README.md)와 [파일별 조사표](D:/01_Study/02_OpenGL/Onedow/Docs/QA/CodeStructure_Audit_2026-10-12/File_Coverage.md)에 게임 소스 98개·테스트 7개·보조 파일 24개, 40개 검토 묶음과 include/호출/전역 참조 근거를 기록했다. 자동 후보 수는 실제 중복 규칙 수와 구분한다. 빌드·실행 검증 및 최종 클래스/API 설계는 완료 범위에 포함하지 않는다.

선행 실행 항목은 FIX-01~03과 BEH-01/02다. 0단계의 남은 설계 결과물은 규칙 소유자·처치 정책·런 상태 보존표·통합 인터페이스다. A 항목의 REG-01~06/26 명세를 마련했으나 테스트 구현/실행은 아직 없다. 특히 AddKillCombo의 무한 세례 부수효과와 미정 규칙을 정리하고, BEH 수정 후 기준 검증을 통과시킨 뒤 2단계 보상 구조 통합을 진행한다.

보상은 첫 구조 통합 묶음이며 앞선 결함/동작 수정과 구분한다. 미결 규칙은 관련 구현에만 영향을 주도록 분리하고, 콘텐츠·밸런스 개발은 합의한 공통 경로 사용 규칙 아래 계속한다.
