# 경험치 곡선·소수 XP 이관 계획

2026-10-13 기준. 구현 전 조사와 작업 계획, 구현 후 검증 결과를 함께 기록한다. 기존 구조 작업의 원칙은 [중복 리팩터링 계획](Duplication_Refactor_Plan_2026-10-12.md)을 따른다. 확정된 **성장 곡선 변경**과 **XP 자료형·경로 정리**를 별도 작업으로 검증한다.

**작업은 아래 단계 ID와 순서를 따라 한 단계씩 진행한다.** 각 단계의 선행 검증과 완료 조건을 충족하고 기록하기 전에는 다음 단계로 넘어가지 않으며, XP와 무관한 웨이브·전투 구조 변경은 이 계획의 단계에 끼워 넣지 말고 별도 계획으로 분리한다.

## 확정된 목표와 구현안

- 다음 레벨 필요 XP의 수식은 `6 × 현재 레벨^2.4`다. 레벨 1의 필요 XP는 **6**이다. `flatFloor=20`은 제거한다. 수식과 다른 주석의 예시 값은 실제 계산 결과로 고친다.
- 필요 XP는 현행처럼 정수 문턱값으로 둔다. 수식 결과를 **내림**한다. 예: 레벨 1은 6, 레벨 2는 31, 레벨 3은 83, 레벨 5는 285. 표와 주석은 동일한 계산·반올림 규칙을 사용한다.
- 소수 XP 전환의 구현안은 획득·보유 XP를 소수 셋째 자리까지 보존하는 것이다. 보상 한 번의 계산 결과를 0.001 XP 단위로 가장 가까운 값에 반올림하고, 이후 이동·분배·합산에서는 다시 반올림하지 않는다. 음수·비정상 배율과 오버플로 처리도 한 계산 함수에서 정의한다.
- 일반 몹 XP는 `(종류별 기본 XP + 공통/종류별 추가 XP) × xpMult`, 스코프 XP는 `(기본 XP + rangedXpBonus) × xpMult`, 지속 XP는 `xpPerSec × xpMult × 경과 시간`이다. 배율은 보상의 합계에 한 번만 적용한다. 점수의 스웜 20% 배율을 XP에 적용하지 않는다.
- 처치 XP는 기존처럼 별가루 픽업에 실려 **수거할 때** 지급한다. 제네시스·퀘이사의 지연 드롭과 투척 스웜의 XP 제외는 유지한다. XP·점수·스타더스트 자격을 각각 판정한다.
- 한 런의 일반 레벨 상한은 45이며, 큰 픽업이 여러 레벨을 넘길 때 남은 XP를 다음 레벨로 이월한다. 창의적 모드의 상한 우회와 기존 수동 레벨업 기록은 별도 정책 변경 없이 보존한다.

0.001 XP는 내부 최소 단위로 권장한다. `int64_t` 기반의 작은 `XpAmount` 값 형식 또는 명확한 단위 이름을 가진 정수 저장소를 한 곳에 두고, UI·로그 경계에서만 사람이 읽는 XP로 변환한다. 부동소수점 누산값을 플레이어 상태와 드롭에 그대로 저장하면 조각 분배와 레벨 문턱 비교가 흔들리므로 피한다. 지속 XP 계산에 필요한 0.001 XP 미만 잔량만 `double`로 이월한다. 리셋 시 그 잔량도 초기화한다. 이 형식과 변환 함수는 표준 라이브러리만 사용하며 렌더러·전역 게임 상태에 의존하지 않는다.

## 구현 전 불일치와 변경 범위

| 지점 | 현재 상태 | 목표 |
|---|---|---|
| `ExpSystem::Required` | 주석은 `6 × L^2.4`와 첫 6 XP를 설명하지만 코드에는 `+20`이 있어 첫 레벨이 26 XP다. 함수 위 주석의 36 XP도 코드와 다르다. | 수식과 내림 규칙을 한 곳에 두고 예시 주석을 그 결과로 갱신한다. |
| `MobExperienceReward`, `RangedMob::ExperienceReward` | `long long` 변환으로 `1 × 1.03` 같은 보너스가 잘린다. | 공통 XP 변환을 사용해 1.030 XP를 보존한다. 몹별 기본값과 보너스 종류는 유지한다. |
| `SpawnKillStardust` → `pendingDustXp` → `SpawnStardust` → `StardustPickup::xpValue` | 모든 전달 단계가 정수 XP다. | 소수 단위로 전달하고 모든 조각의 XP 합이 원 보상과 정확히 같게 한다. 지연 드롭도 동일하다. |
| `GameManager::xp`, `g_XpTimeAccum`, 레벨업/HUD | 처치 XP는 정수로 보유한다. 지속 XP는 1 XP가 될 때까지 별도 누산한다. | 지급 진입점과 문턱 비교를 공통 단위로 통일한다. 지속 XP의 소수도 진행률에 반영한다. |
| `GameplayTelemetry`, 디버그/REG 스모크 | XP 인자·누적치·표시 일부가 `long long` 및 정수 서식이다. | 기존 `_xp` 필드명은 유지하고 값은 **XP 단위 소수**로 기록한다. milli-XP 원시 정수를 그대로 기록하지 않는다. 가이드·스모크 기대값을 함께 갱신한다. |

자료형 전파는 `WiNILL/Entity/ExpSystem.h`, `Monster.h`, `RangedMob.h`, `CollisionSystem.h`, `KillRewards.h`, `WiNILL/Render/Juice.h`, `WiNILL/Core/GameManager.h/.cpp`, `WiNILL/main.cpp`, `WiNILL/System/GameplayTelemetry.h`와 관련 테스트에 걸친다. 위치는 줄 번호가 아닌 함수·필드 이름으로 추적한다. `CollisionSystem::Update`의 미사용 `xp` 참조 인자는 호출부를 확인한 뒤 제거한다. 다른 런·스탯 리팩터링과 섞인 변경은 피한다.

## 작업 순서와 완료 조건

| 작업 | 구현 범위 | 선행 회귀 검증 및 완료 조건 |
|---|---|---|
| XP-01: 현행 경로 고정 | 새 동작 변경 전 XP 생산·운반·지급·표시 경로를 테스트로 기록한다. | REG-01의 5개 처치 경로×처치 수단, 투척 스웜, 제네시스·퀘이사 지연 지급, 별가루 여러 조각 합계, REG-04 런 재시작을 기준으로 삼는다. 테스트는 현행 상태에서 먼저 통과해야 한다. |
| BEH-XP-01: 성장 곡선 | `Required`에서 바닥값을 제거하고 수식·내림·예시 주석을 일치시킨다. | 레벨 1/2/3/5/10/45의 문턱값, 레벨 1의 5.999/6.000 XP 경계, 다중 레벨업·45 상한·창의적 모드를 검증한다. 이 작업의 결과가 소수 XP 이관 없이도 독립적으로 판정되어야 한다. |
| XP-02: 단위와 보상 계산 | 공통 XP 양·변환/서식 규칙을 만들고 일반 몹·스코프·초당 XP 생산자에 적용한다. | 기본 XP, 공통·로터·종류별·스코프 보너스, `xpMult` 조합을 비교한다. `1×1.03=1.030`, `(1+1)×1.03=2.060`, `0.5×1.03=0.515 XP/s`를 보존한다. 배율 중복·정수 절삭이 없어야 한다. |
| XP-03: 드롭·런 상태·레벨업 | 지연 보상과 픽업의 XP 자료형을 이관하고, 지급을 한 진입점으로 모아 보유 XP·텔레메트리를 함께 갱신한다. 레벨업·리셋·HUD를 같은 단위로 읽는다. | 생성 XP = 지연 XP 또는 현장 조각 XP의 합, 수거 XP = 런 증가량 = 텔레메트리 획득량이어야 한다. 0.001 XP만 담은 드롭, 여러 조각, 큰 픽업, 반복 수거 방지, 런 재시작 잔량 초기화를 검증한다. |
| XP-04: 출력·문서·잔존 경로 | 디버그 출력, 스모크 입력/출력, 텔레메트리·가이드를 갱신하고 정수 XP 경로를 전수 검색한다. | 로그 필드에 `1.030` 같은 XP 단위 값이 기록되고 레벨업 전후·구간 합계가 맞아야 한다. `long long` XP 전달, 직접 `g_GameManager.xp +=`, 정수 `%lld` 서식, 낡은 XP 주석이 남지 않아야 한다. |

각 작업은 테스트와 코드를 함께 이관한 뒤 다음 작업으로 넘어간다. 새 몹·증강을 병행 개발하더라도 XP-02 이후의 새 XP 보상은 공통 계산 경로를, XP-03 이후의 새 지급은 공통 지급 경로를 사용한다. XP 외 보상 통합(REG-01)의 정책은 이 계획에서 다시 정의하지 않는다.

## 검증 매트릭스

1. **보상:** 일반 몹 종류별 기본값, 공통/종류별/로터 추가값, 스코프 전용 추가값, 다중 XP 배율; 탄환·레이저·공통 사망 수거 경로에서 같은 대상은 같은 XP를 만든다.
2. **드롭:** 즉시 드롭, 제네시스·퀘이사 지연 드롭, 스타더스트 0개인 XP 보상, 1/여러 조각 분할, 투척 스웜 0 XP. 생성·분배·수거 단계마다 합계가 보존된다.
3. **시간:** 0.5 XP/s 및 배율 적용, 프레임 시간 분할이 달라도 누적량 차이가 최대 0.001 XP 이내인지, 짧은 런 종료/재시작 때 미지급 잔량이 새 런에 넘어가지 않는지 확인한다.
4. **레벨:** 문턱값 바로 아래/같음/초과, 한 번에 여러 레벨 상승, 일반 45 상한, 창의적 모드, 픽업 이후 HUD 진행률을 확인한다.
5. **기록:** `RecordExperience`와 `LEVEL_UP` 전후 XP, `SAMPLE`의 현재·필요·구간·총 XP가 플레이어 상태와 같은 단위인지 확인한다. 텔레메트리 비활성 상태에서도 XP 지급이 정상이어야 한다.

관련 기존 스크립트(`scripts/test_reg01_kill_rewards.ps1`, `scripts/test_reg04_run_reset.ps1` 등)를 먼저 실행하고, 새 XP 전용 단위 테스트와 게임 빌드를 마지막에 실행한다. 플랫폼 빌드가 CI에 의존하는 환경이면 Windows 로컬 결과와 macOS CI 결과를 구분해 기록한다. 이미 수정 중인 다른 파일의 변경은 덮어쓰지 않는다.

## 구현·검증 기록 (2026-10-13)

XP-01~04와 BEH-XP-01을 구현했다. `Experience.h`가 XP 최소 단위·생산 시 반올림·서식·초당 XP 잔량을 소유한다. 처치·스코프 보상, 지연 드롭, 픽업, 런 상태, 레벨업, 텔레메트리는 이 단위를 사용한다. `GrantExperience`가 게임 실행 중 픽업·초당 XP·스모크 입력의 공통 지급 지점이다. `CollisionSystem::Update`에서 쓰지 않던 XP 참조 인자를 제거했다.

검증: Windows Release 빌드, `test_experience.ps1`(곡선·문턱·초당 XP·로그), `test_reg01_kill_rewards.ps1`(처치 수단별 소수 보상·드롭 분배 포함), `test_reg02_03_stat_builds.ps1`(XP 관련 증강·재계산 포함), `test_kill_lifesteal.ps1`, `test_thrown_swarm_kill.ps1`, `test_quasar_nova.ps1`, `test_reg04_run_reset.ps1`, `test_experience_smoke.ps1`(실행 파일의 다중 레벨업·상한·0.001 XP 픽업)을 통과했다. macOS CI는 로컬 변경을 업로드하지 않아 이번 구현에 대해 아직 실행되지 않았다.
