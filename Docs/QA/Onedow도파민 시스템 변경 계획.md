# Onedow 도파민 시스템 변경 계획

> 목적: 히트스톱과 콤보 마일스톤 숫자 강조를 실험적으로 추가한다. 두 변경은 각각 함수와 호출 지점을 분리해, 평가 후 해당 부분만 되돌릴 수 있게 한다.
> 범위: 기존 QA 문서의 4-2 중 히트스톱과 4-1 중 마일스톤의 시각 강조에 한정한다. **4-3 콤보 보상은 제외한다.**

## 1. 합의된 기준

| 항목 | 기준 |
|---|---|
| 히트스톱 대상 | 현재 `CollisionTier` 4인 `GENESIS`, `QUASAR` 처치 |
| 엘리트 지속 시간 | 0.03초 |
| 보스 지속 시간 | 보스 분류가 코드에 추가될 때 0.05초로 확장 |
| 발동 상태 | `GameState::RUNNING`에서만 |
| 발동 지점 | `!alive && !exploded` 공통 사망 처리 분기 |
| 중첩 | 기존 `TriggerHitStop()`의 최장 잔여 시간 우선 규칙 사용 |
| 히트스톱 동작 범위 | 기존 `physDelta = 0` 흐름 재사용. 시뮬레이션만 멈추고 실제 delta 기반 시스템은 계속 갱신 |
| 히트스톱 시험 토글 | 실행 때 켜짐, 저장하지 않음. Debug Mode의 Debug Toolkit Stats 탭에서 조작 |
| 토글 영향 | 새 엘리트 처치 히트스톱만 제어. 기존 히트스톱 호출은 그대로 유지 |
| 마일스톤 발동 수 | 10, 25, 50, 100회, 이후 50회 간격 유지 |
| 마일스톤 연출 | 현재 콤보 숫자의 확대·금색 펄스만 강화. 표식, 전체 화면 연출, 효과음 없음 |
| 마일스톤 펄스 길이 | 기존 0.7초 유지 |
| 마일스톤 토글 | 별도 토글 없이 연출 함수만 분리 |

### 티어 판정 주의

`MonsterManager::CollisionTier()`는 Genesis와 Quasar를 모두 4로 분류한다. `CombatTier()`는 전투 내부 역할을 위한 별도 기준이며 Quasar가 3이다. 히트스톱 대상은 충돌 우선순위 함수에 결합하지 않고, 실험 함수 안에서 `MobKind::GENESIS`와 `MobKind::QUASAR`를 명시해 판정한다. 보스 유형이 추가되면 그때 대상 판정과 0.05초 지속 시간을 확장한다.

## 2. 현재 코드 흐름

- `WiNILL/Render/Juice.h`의 `TriggerHitStop(float)`은 잔여 시간이 더 긴 경우에만 타이머를 갱신한다.
- `WiNILL/main.cpp`은 `g_HitStopTimer`를 감소시키고, 남은 시간이 있을 때 고정 전투 업데이트의 `physDelta`를 0으로 둔다. 기존의 플레이어 이벤트 히트스톱도 이 흐름을 쓴다.
- 몬스터 공통 사망 처리 분기는 일반 몬스터 처치들을 모아 `SpawnDeathEffect()`를 시작한다. 이 분기는 `RUNNING` 외에 `DYING`에서도 실행되므로 새 호출부에 별도 `RUNNING` 조건이 필요하다.
- `Juice.h`의 `ComboIsMilestone()`은 현재 합의된 마일스톤을 판정하고, `AddKillCombo()`가 달성 시 `g_ComboMilestone`을 0.7초로 설정한다.
- HUD는 남은 `g_ComboMilestone` 비율로 콤보 숫자의 크기와 금색 강조를 계산한다.
- Debug Toolkit은 `Debug Mode`일 때 열리며 Stats 탭에 런타임 토글 버튼이 이미 있다.

## 3. 변경 계획

### 3-1. 엘리트 처치 히트스톱

1. `main.cpp`에 실험 전용 헬퍼를 둔다. 헬퍼는 토글이 켜져 있고 상태가 `RUNNING`이며 몬스터 종류가 Genesis 또는 Quasar일 때만 `TriggerHitStop(0.03f)`를 호출한다.
2. 헬퍼 호출을 `!m->alive && !m->exploded` 분기에 한 번 추가한다. 호출은 사망 연출 시작 부근에 둔다. 분기 자체가 한 번만 처리되므로 동일 몬스터의 중복 발동을 피한다.
3. 새 토글 상태는 `main.cpp`에서 실행 시 `true`로 초기화하고 저장 설정에는 연결하지 않는다.
4. `DebugToolkitContext`에 해당 상태 참조를 전달하고, Stats 탭에 켜짐/꺼짐 버튼을 추가한다. 이 버튼은 새 엘리트 처치 헬퍼만 제어한다.
5. 기존 `TriggerHitStop()`과 플레이어 이벤트 호출부는 유지한다. 동시 처치는 기존 최장 시간 우선 규칙으로 처리한다.

#### 지속시간 타이밍 제한

처치 분기는 고정 업데이트 안에서 실행되지만 `physDelta`와 타이머 감소는 해당 업데이트 전에 계산된다. 따라서 새 호출의 효과는 다음 바깥 루프부터 적용되며, 현재 타이밍을 그대로 재사용하면 0.03초의 체감 길이가 프레임률과 catch-up 업데이트 수에 따라 달라질 수 있다. 이번 실험에서는 변경 최소화를 위해 이 기존 타이밍을 그대로 사용한다. 지속시간을 프레임률과 무관하게 보정하는 별도 pending 처리나 메인 루프 순서 변경은 포함하지 않는다.

### 3-2. 콤보 마일스톤 숫자 강조

1. 마일스톤 판정, 콤보 증가, 보상 처리에는 손대지 않는다. 현재 기준과 0.7초 타이머를 그대로 둔다.
2. HUD에서 계산하는 마일스톤 숫자 스타일을 전용 헬퍼로 분리한다. 해당 헬퍼 안에서만 기존 확대와 금색 강조의 강도를 높인다.
3. 강도 값은 한 곳에서 조절 가능하게 둔다. 새 표식, 효과음, 화면 가장자리 효과, 화면 전체 플래시, 추가 토글은 만들지 않는다.

## 4. 되돌리는 방법

### 히트스톱 실험 제거

- 공통 사망 분기의 실험 헬퍼 호출을 제거한다.
- 엘리트 처치 전용 헬퍼와 실행 중 토글 상태를 제거한다.
- Debug Toolkit의 context 참조, Stats 탭 버튼과 입력 처리를 제거한다.
- 기존 `TriggerHitStop()` 정의와 다른 시스템의 호출은 남긴다.

### 마일스톤 강도 실험 제거

- HUD 전용 스타일 헬퍼와 그 호출을 제거하거나 기존 계산으로 복구한다.
- 원래 숫자 확대 계수와 금색 강조를 복원한다.
- `ComboIsMilestone()`, `g_ComboMilestone`, `AddKillCombo()`의 기존 마일스톤 기능은 유지한다.

두 변경은 별개로 되돌릴 수 있게 구현한다. 한쪽을 유지하고 다른 쪽만 제거할 수 있어야 한다.

## 5. 범위 밖

- **4-3 콤보 보상**: 흡수 반경, 스킬 쿨다운, 경험치, 공명 버프 등 보상 추가를 하지 않는다.
- 콤보 피치 사다리, 콤보 끊김 음, 마일스톤음, BGM 레이어 등 사운드 변경을 하지 않는다.
- 화면 흔들림, 크리티컬 단계화, 데미지 숫자 병합, 조합 시너지 변경을 하지 않는다.
- 보스가 코드에 추가되기 전에는 보스용 히트스톱 호출을 만들지 않는다.

## 6. 구현 후 수동 확인 항목

- Debug Mode Stats 탭 토글의 초기값이 켜짐이며 재실행 후에도 설정 파일에 저장되지 않는지 확인한다.
- 토글을 끄면 Genesis·Quasar 처치 히트스톱만 꺼지고 기존 플레이어 이벤트 히트스톱은 계속 작동하는지 확인한다.
- Genesis·Quasar 처치와 일반 몬스터 처치, `RUNNING`과 `DYING` 상태를 나눠 발동 범위를 확인한다.
- 여러 대상이 같은 업데이트에서 처치될 때 히트스톱 시간이 누적되지 않고 기존 최장 시간 규칙을 따르는지 확인한다.
- 콤보 마일스톤 기준과 0.7초 길이가 유지되고, 마일스톤 동안 숫자 확대·금색 강조만 강해졌는지 확인한다.
- 보상, 효과음, 전체 화면 연출 등 범위 밖 변경이 섞이지 않았는지 확인한다.

## 7. 주요 코드 위치

- `WiNILL/Render/Juice.h`: 히트스톱 타이머, 콤보 마일스톤 판정과 타이머
- `WiNILL/main.cpp`: 타이머 적용, 공통 사망 처리, 콤보 HUD
- `WiNILL/Entity/MonsterManager.h`: 충돌 티어와 전투 티어 정의
- `WiNILL/System/DebugToolkit.h` / `DebugToolkit.cpp`: Stats 탭 상태 연결과 토글 UI
