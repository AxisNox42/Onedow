# 웨이브 전환 리팩터링 계획

2026-10-13 기준. 경험치 리팩터링 계획의 단계 진행 원칙을 따라 웨이브 변경은 XP 단계와 분리한다. 각 단계의 범위와 완료 조건을 먼저 고정하고, 선행 단계의 확인 전에는 다음 단계의 동작을 섞지 않는다. [경험치 리팩터링 계획](Experience_Refactor_Plan_2026-10-13.md)

## 확정된 목표

- 한 웨이브는 전투 시간 180초다.
- 웨이브가 끝나면 디버프 증강 1개를 무작위로 추첨해 선택 화면 없이 즉시 적용한다.
- 각 레벨업은 버프 증강 3개 중 1개를 고른다. 디버프를 뒤이어 고르는 레벨업 보상은 없으며, 후보는 현재 최대치·중복 제한을 따른다.
- 웨이브 사이 정비 구간은 없다. 웨이브 경계에서 멈춤 없이 다음 웨이브로 이어진다.
- 런은 유한한 웨이브로 끝난다. 현재 최종 웨이브 수는 10이며, 난이도를 입력받는 함수로 결정해 향후 난이도별 값을 분리할 수 있게 한다.
- 10번째 웨이브 생존 완료 시 승리 결과 화면을 표시한다. 마지막 웨이브 뒤에는 다음 웨이브가 없으므로 디버프를 지급하지 않는다.
- 기존 시간 기반 난이도 증가를 우선 유지한다. 별도 웨이브 난이도 배율은 추가하지 않는다.
- 인게임 점수와 현재 별가루 HUD는 표시하지 않는다. 점수는 런 종료 통계에서 표시한다.
- 웨이브 HUD는 배경 패널 없이 실제 원형 다섯 개를 중앙 정렬한다. 완료 웨이브는 채우고, 현재 웨이브는 큰 테두리 원으로 강조한다. 타이머 글자 크기는 유지하며 원과 충분한 간격을 둔다.

## 작업 단계와 완료 조건

| 단계 | 작업 범위 | 완료 조건 |
|---|---|---|
| WAVE-01: 현재 흐름과 경계 고정 | `g_GameTime`, 게임 상태, 적 스폰/시간 기반 난이도, 런 종료 지점을 확인한다. 정비 구간 없이 이어가는 규칙을 기록한다. | 웨이브 시간의 기준, 일시정지·레벨업·사망 중 시간 처리, 경계 프레임 소유자가 확정된다. |
| WAVE-02: 레벨업 보상을 버프로 한정 | 레벨업 보상 큐에서 디버프 선택 단계를 제거한다. 크리에이티브 수동 레벨업도 버프 후보만 쓴다. | 모든 레벨업 경로에서 버프 3장 선택 후 전투로 복귀하며 디버프 선택이 이어지지 않는다. |
| WAVE-03: 웨이브 모델 | 경과 전투 시간으로 현재 웨이브를 계산하고, 난이도 인자를 받는 최종 웨이브 수 함수를 둔다. 현재 모든 난이도 결과는 10이다. | 180초 경계의 인덱스와 남은 시간이 정확하고, 난이도별 최종 웨이브 규칙을 함수 한 곳에서 바꿀 수 있다. |
| WAVE-04: 자동 디버프와 종료 | 다음 웨이브가 시작될 경계에서 유효 디버프 한 개를 추첨·즉시 적용한다. 마지막 웨이브 뒤에는 다음 웨이브를 만들지 않고 승리 결과로 전환한다. | 디버프가 2~10웨이브 경계에서 한 번씩만 적용되고, 유효 후보가 없을 때 안전하게 진행하며, 최종 경계에서 승리 결과가 한 번만 기록된다. |
| WAVE-05: HUD와 결과 표시 | 인게임 점수·현재 별가루 표시를 제거한다. 배경 패널 없이 중앙 상단에 완료/현재/예정 웨이브를 나타내는 실제 원형 다섯 개와 남은 시간을 간격을 두고 표시한다. 점수와 마지막 웨이브 승리는 종료 결과 화면에서 표시한다. | 원의 채움 상태와 남은 시간이 런 상태와 일치하고, 확대된 원과 타이머가 겹치지 않으며, HUD와 결과 화면이 기존 레벨업·일시정지 화면과 충돌하지 않는다. |
| WAVE-06: 디버그 전환 | F1 디버그 콘솔의 능력치 탭에서 다음 웨이브로 즉시 이동한다. 일반 시간 경계와 같은 전환 함수를 호출한다. | 클릭마다 다음 웨이브와 디버프가 한 번 적용되고, 최종 웨이브에서는 추가 디버프 없이 승리로 끝난다. |
| WAVE-07: 웨이브 적 출현 | [적 출현 설계](Wave_Enemy_Spawn_Design_2026-10-13.md)에 따라 현재 선택 가능한 보통 난이도의 일반 몹 3티어 상한, 3분 내 밀도 증가, 5의 배수 웨이브의 4티어 정기 엘리트를 적용한다. 쉬움·어려움 및 5티어는 향후 설계로 둔다. | 현재 10웨이브에서 일반 몹은 최대 3티어이며 5·10웨이브에만 4티어 정기 엘리트가 한 번씩 나온다. |

현재 전투 시계는 `g_GameTime`이며, `Difficulty`는 EASY/NORMAL/HARD 세 값을 갖지만 새 런 시작 시 NORMAL로 초기화된다. 최종 웨이브 함수는 이 기존 상태를 입력으로 받아 지금은 10을 반환한다.

WAVE-01 코드 경로 조사는 완료했다. WAVE-02~05의 구현을 반영했다. WAVE-02~04의 전체 동작 검증은 남아 있으며, WAVE-05 HUD 검증 결과는 아래에 기록한다.

## WAVE-05 HUD 변경·검증 (2026-10-13)

- `main.cpp`의 인게임 점수·현재 별가루 HUD와 전투 중 창 제목의 점수 표시를 제거했다. 점수 누적과 종료 통계 표시를 유지한다.
- 문자 `o`/`O`를 원형 삼각형 메시로 교체했다. 현재 원은 반지름 `12 × hudScale`, 주변 원은 `8 × hudScale`, 중심 간격은 `30 × hudScale`이다. 완료 원은 채우고 예정 원은 테두리만 표시한다. 런 범위 밖의 자리만 흐리게 표시한다.
- 타이머 크기는 기존 배율을 유지한다. 원 아래쪽부터 타이머 기준 위치까지 `14 × hudScale` 간격을 둔다. 도형 배치를 명시적으로 출력한 뒤 타이머를 그린다.
- `scripts/build_windows.ps1`의 Windows x64 Release 빌드와 `git diff --check`를 통과했다.
- `scripts/smoke_ui.ps1`로 1280×720과 1920×1080에서 1·4·10웨이브 HUD를 캡처했다. 중앙 정렬, 원/타이머 간격, 완료/현재/예정 구분, 점수·현재 별가루 HUD 제거를 시각적으로 확인했다. 1920×1080 일시정지 캡처와 1280×720 종료 통계의 최종 점수 표시도 확인했다.
- 캡처: [1280×720 4웨이브](../../build/smoke/wavehud_final_720/wavehud_final_720_KR_02_WAVETIME=540.png), [1920×1080 10웨이브](../../build/smoke/wavehud_final_1080/wavehud_final_1080_KR_03_WAVETIME=1620.png), [종료 통계](../../build/smoke/wavehud_final_720/wavehud_final_720_KR_04_GAMEOVER.png).

스모크 전용 `WAVETIME=<전투 초>` 단계로 HUD 상태를 직접 지정했다. 이 캡처는 화면 표시를 검증하며, 실제 180초 경계를 통과하는 디버프 지급·승리 판정의 전체 동작 검증을 대신하지 않는다.

## WAVE-06 디버그 전환 검증 (2026-10-13)

- F1 디버그 콘솔의 능력치 탭 하단에 `다음 웨이브` 버튼을 추가했다. 전투 중에만 활성화하며, 클릭 시 현재 웨이브의 180초 경계로 이동해 일반 전환 함수를 실행한다.
- Windows x64 Release 빌드와 1280×720 UI 스모크를 통과했다. 디버그 버튼 클릭 결과 1→2웨이브에서 디버프 1개, 2→3웨이브에서 디버프 1개가 즉시 추가됐다. 10웨이브에서 클릭하면 디버프 추가 없이 승리 결과로 전환됐다.
- 스모크 상태 기록: `wave=1, owned=0` → `wave=2, owned=1` → `wave=3, owned=2` → `wave=10, owned=2` → `waveVictory=1, owned=2`. 마지막 웨이브 시작 위치 설정에는 HUD 스모크 전용 `WAVETIME=1620`을 사용하고, 마지막 경계는 실제 디버그 버튼으로 넘겼다.
- 캡처: [2웨이브 HUD](../../build/smoke/wave_debug_qa/wave_debug_qa_KR_04_WAIT.png), [승리 결과](../../build/smoke/wave_debug_qa/wave_debug_qa_KR_11_REG04DUMP=VICTORY.png).
