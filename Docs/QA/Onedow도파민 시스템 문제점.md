## 1. 한눈에 보는 진단

> **구조(증강, 등급, 별자리 테마)는 이미 탄탄하다. 부족한 것은 "소리"와 "증강끼리 반응하는 순간"이다.**

| 영역 | 상태 | 판단 |
|---|---|---|
| 증강 등급 체계 | 일반, 희귀, 에픽, 전설, 신화, 조합 | 충분 |
| 별자리 테마 일관성 | 적, 증강 선택, 게임오버 계획까지 통일 | 강점 |
| 시각 연출 기반 | 데미지 숫자, 스파크, 잔상, 히트스톱, 플래시, 콤보 | 기반 있음, 적용 범위가 좁음 |
| 사운드 | 구현된 SFX 2개(Shoot, Kill) | **최대 약점** |
| 콤보 | 표시만 있고 보상 없음 | 약점 |
| 증강 시너지 | 조합 4종, 전부 스탯 패키지 | **최대 기회** |

---

## 2. 현재 구조의 강점

1. **별자리 테마가 전체를 관통합니다.** 적은 "코어 + 별 노드 + 연결선"으로 설계됐고, 증강 선택도 별자리입니다. 새 연출은 이 언어 안에서 확장하면 됩니다.
2. **신화 등급이 메커니즘을 바꿉니다.** 예: 무한 세례는 처치마다 쿨다운이 줄어드는 스노우볼형입니다.
3. **디버프가 EXP 보상과 연결돼 있습니다.** 위험을 감수하는 선택의 뼈대가 이미 있습니다.
4. **경험치가 별가루 픽업에 실립니다.** 레벨업이 "줍는 순간"에 걸려 있어 사운드와 연출을 붙이기 좋습니다.
5. **눈뽕 방지 원칙이 있습니다.** 콤보 마일스톤에 전체화면 번쩍임을 쓰지 않았고, 파티클에 `reduced` 옵션이 있습니다. 연출을 늘릴 때의 안전장치가 이미 있는 셈입니다.

## 3. 문제점 (코드 근거)

| # | 발견 | 근거 | 영향 |
|---|---|---|---|
| 1 | 구현된 SFX가 2개뿐 | `Audio::Sfx`에 Shoot, Kill만 존재. 사운드 TODO 문서에는 60개 이상 계획 | 매우 큼 |
| 2 | 킬 사운드가 콤보와 무관 | `AddKillCombo()`가 같은 음을 재생, 피치는 ±10% 랜덤 변주 | 큼 |
| 3 | 콤보 마일스톤에 소리가 없음 | 주석에는 "칩 사운드"가 있으나 해당 함수 내 호출이 보이지 않음 | 큼 |
| 4 | 콤보가 보상이 아님 | `g_Combo`는 HUD 숫자와 색만 변경 | 큼 |
| 5 | 일반 킬에 히트스톱·쉐이크 없음 | `TriggerHitStop`, `g_ShakeTime`이 플레이어 대형 이벤트(`main.cpp` 약 1735, 1804, 2150행)에서만 보임 | 중간 |
| 6 | 조합 4종이 스탯 패키지 | 피의 군주, 전쟁군주, 철벽, 구명부표. 시각 반응 없음 | 큼 |

| 8 | 일반 증강이 눈에 안 보임 | 공격력, 연사, 탄속, 재생 증가는 화면 변화 없음 | 중간 |

## 4. 개선 설계

### 4-1. 사운드 (효율 최고)

**① 콤보 음계 사다리**

킬마다 피치를 음계처럼 올립니다. 5음 음계로 양자화하면 아무리 연속으로 터져도 불협화음이 되지 않습니다.

```cpp
// Audio.h
void PlaySfx(Sfx s, float pitch = 1.0f);

// Juice.h  AddKillCombo()
static const int kSteps[] = { 0, 2, 4, 7, 9, 12, 14, 16, 19, 21, 24 };  // 5음 음계
int idx = std::min(g_Combo / 2, 10);
float pitch = powf(2.0f, kSteps[idx] / 12.0f);
Audio::PlaySfx(Audio::Sfx::Kill, pitch);
```

- Kill 효과음의 랜덤 피치 변주(`pitchVary`)는 끄거나 ±3% 이하로 줄입니다. 랜덤이 크면 사다리가 묻힙니다.
- 콤보가 끊길 때는 짧은 하강음을 넣습니다. "끊겼다"는 아쉬움이 다음 콤보의 동기가 됩니다.

**② 별가루 흡수음 연속 피치**

0.3초 안에 연속 흡수하면 피치가 올라가고, 경험치 바가 차는 동안 같은 음이 이어져서 레벨업음으로 해소됩니다.

**③ 마일스톤음**

10/25/50/100(이후 50 단위)마다 종소리나 베이스 한 방을 넣습니다. 시각은 지금처럼 절제하고 소리로 보상합니다.

**④ 콤보 구간별 BGM 레이어**

TODO 문서의 구간(0–50, 51–200, 201–500, 501–2000, 2001+)을 그대로 쓰되, 별도 곡이 아니라 **기존 BGM 위에 스템을 추가**하는 방식을 권장합니다. 에셋 부담이 가장 적습니다.

**⑤ 대량 처치 시 겹침 제한**

`SfxDef`의 `minMs`로 같은 효과음의 최소 간격을 둡니다. 스웜 같은 물량 적에서 소리가 뭉개지면 오히려 쾌감이 줄어듭니다.

**⑥ 증강 확정 3단계 사운드**

### 4-2. 타격감 레이어

| 항목 | 내용 |
|---|---|
| 마이크로 히트스톱 | 엘리트·대형 적 처치에만 0.03~0.05초. 잡몹에는 넣지 않음 |
| 약한 쉐이크 | 위력 비례. 같은 이벤트에 히트스톱과 함께 적용 |
| 크리티컬 단계화 | 일반 → 크리 → 고배율 크리 3단계. 숫자 크기, 스파크 색, 짧은 소리로 구분 |
| 데미지 숫자 병합 | 정전기장 펄스, 연쇄 폭발의 같은 프레임 틱을 합산해 큰 숫자 하나로 표시. 현재 상한(Windows 140 / macOS 90)에 닿으면 앞 숫자부터 삭제되는 문제 해소 |
| 별자리 처치 연출 | 적이 별자리 그래프이므로, 죽을 때 노드가 코어에서 먼 순서로 하나씩 꺼지고 연결선이 별가루로 변해 플레이어에게 흘러감. 기존 `NodeAnchor` 데이터 활용, 새 파티클 시스템 불필요 |
| 창(window) 연출 | 가짜 창, `WindowFx`, "창 닫기" 스킬이 있는 구조를 살려 신화 획득이나 대폭발 때 창이 살짝 튀거나 번지게 함. **끌 수 있는 설정 필수** |

### 4-3. 콤보를 보상으로

현재 콤보는 숫자만 오릅니다. 구간마다 실제 이득을 줘서 "끊기지 않으려는" 동기를 만듭니다.

| 콤보 | 보상 안 |
|---|---|
| 10 | 별가루 흡수 반경 증가 |
| 25 | 액티브 스킬(Q/E/R) 쿨다운 가속 |
| 50 | 경험치 소폭 증가 |
| 100+ (50마다) | 짧은 "공명" 버프, 화면 가장자리 색 변화 |

- 콤보 유지 시간(`COMBO_WINDOW` 3초)이 적절한지는 텔레메트리 로그의 킬 간격 분포를 보고 판단합니다.
- 보상 수치는 처음엔 약하게 시작해서 로그로 조정하세요.

### 4-4. 시너지 시스템 (최대 기회)

**① 태그 연결**

`AugSubsystem`을 비트마스크 태그로 확장하고, 두 계열 이상이 만나면 반응 이벤트를 발생시킵니다.

- 현재 `COMBO_DEFS`는 "재료 3개 보유 시 스탯 지급"입니다.
- 반응형 시너지는 **별도 레이어**로 추가하면 기존 세이브 인덱스와 조합 레시피에 영향이 없습니다.

**② 이 게임에 맞는 반응 예시**

| 조합 | 반응 | 시각 포인트 |
|---|---|---|
| 레이저 × 차크람 | 차크람이 프리즘이 되어 빔이 꺾이며 추가 빔 방출 | 궤도 위에서 빔이 별 모양으로 퍼짐 |
| 연쇄 폭발 × 정전기장 | 폭발 범위 안의 적끼리 전기 아크로 연결 | 번개 그물 |
| 차크람 특이점 × 연쇄 폭발 | 끌려와 뭉친 적이 한꺼번에 폭발 | 블랙홀에서 폭죽으로 전환 |
| 탄환 세례 × 드론 | 세례 발동 순간 드론이 동기 점등하며 추가 유도탄 | 드론에서 일제히 발사선 |
| 관통 × 레이저 | 레이저 선상에서 관통탄이 충전되어 피해 증가 | 탄이 빔을 지날 때 색 변화 |
| 시간정지 × 모든 공격 | 정지 중 맞은 피해가 적에게 쌓였다가 해제 순간 일제 폭발 | 정지 중 파편이 쌓이다 해제 때 터짐 |

시간정지 연출은 "참았다가 한 번에 터지는" 해소 구조라 구현 비용 대비 쾌감이 큽니다.

**③ 별자리 완성 연출**

보유 증강을 일시정지 인벤토리나 HUD에서 하나의 별자리로 이어 보여주고, 레시피나 반응이 완성되면 선이 닫히며 이름이 뜹니다. 예: "피의 군주 완성". 빌드 선언과 공유 욕구를 테마 안에서 해결합니다.

**④ 반응 이벤트 구조 (권장)**

```
이벤트: OnFire / OnHit / OnKill / OnPulse / OnSkillUse / OnTimeStopEnd ...
증강:   이벤트를 구독 + 태그 보유
반응:   (태그A ∩ 태그B) 보유 시 해당 이벤트에서 추가 효과 발동
제한:   반응 연쇄 깊이 상한, 같은 프레임 중복 방지
```

### 4-5. 증강 선택 화면

- **카드에 진행도 표시.** "조합까지 2/3", "신화 진화까지 1단계". 지금은 선행 조건이 설명 텍스트에만 있습니다.
- **초반 확정 보장.** 처음 3번의 레벨업에는 눈에 보이는 규칙 변경형(차크람, 쌍발, 드론, 레이저) 카드가 최소 1장 나오게 합니다.
- **스탯 증강의 시각 반응.** 중첩 단계마다 외형이 진화하게 합니다.

| 증강 | 시각 반응 |
|---|---|
| 연사 증가 | 총구 화염이 빨라짐 |
| 탄속 증가 | 궤적이 길어짐 |
| 공격력 증가 | 탄 크기·색 변화 |
| 중첩 4+ | 탄 자체가 별개의 이펙트로 변신 |

---

### 4-6. 신화와 위험 선택

- **신화 획득 컷.** 별자리가 합쳐지는 0.5~1초 전용 연출. 신화는 한 런에 자주 나오지 않으므로 남발 걱정이 없습니다.
- **혼돈·판도라 도박 연출.** 결과를 슬롯처럼 하나씩 공개하고, 좋은 결과는 밝게 나쁜 결과는 어둡게 보여줍니다.
- **디버프 위험도 시각화.** EXP 배율을 HUD에 상시 표시하고, 디버프가 쌓일수록 화면 가장자리 색을 미묘하게 바꿉니다.

---

### 4-7. 런 종료와 메타

계획된 게임오버 연출(점수 카운트업, 별자리, 행성계, 성단 생성)에서 핵심은 **그 런에서 만든 빌드가 별자리 형태로 남는 것**입니다. "더 큰 별자리를 만들고 싶다"가 다음 런의 동기가 됩니다. 신기록 달성음과 카운트업의 피치 상승도 같은 원리입니다.

## 7. 주의사항

1. **연출 수를 제한하세요.** 반응 시너지가 늘수록 화면이 복잡해집니다. 적 오라와 연결선을 얇게 두는 현재 원칙을 시너지 이펙트에도 적용하고, 내 이펙트를 선명하게 두는 우선순위를 유지하세요.
2. **연쇄 깊이를 제한하세요.** 연쇄 폭발, 전기 아크, 처치 시 발동이 서로를 호출하면 무한 루프가 생깁니다. "폭발로 죽은 적은 재폭발 없음" 규칙처럼 반응 단위에도 규칙을 두세요.
3. **플랫폼별 상한을 두세요.** 데미지 숫자(140/90)와 잔상(120/80)처럼 새 연출도 Windows와 macOS에 다른 상한을 적용하세요.
4. **끌 수 있게 만드세요.** 쉐이크, 히트스톱, 창 연출은 설정에서 줄이거나 끌 수 있어야 합니다. 이미 있는 `reduced` 개념을 확장하면 됩니다.
5. **텔레메트리로 검증하세요.** 변경 후 `onedow_gameplay_telemetry.txt`의 분당 경험치와 킬 간격으로 템포가 의도대로 바뀌었는지 비교하세요.
